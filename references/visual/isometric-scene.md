把一块真实的地方（仓库、工厂、园区）、一条流程或一套系统，做成一个固定俯角的微缩模型铺满窗口，数据面板浮在上面。它是 dashboard 排版方向里的 L5，属于**静态视觉阶段**；动效只有 3 处，写在第 9 节。

- 项目已经有 `DESIGN.md` → 颜色、字体、圆角用项目的，这里的色值只是没有 token 时的起始值。
- 这份只管场景。面板里的图表用 `references/recipes/chart.md` 的 D 系列，玻璃面板怎么做见 `references/visual/glassmorphism.md`。
- 读的人默认是客户，不懂技术：先保证看得懂、读得准，再谈好看。

## 1. 先过一道关：该不该上 3D

3D 擅长回答位置和关系，不擅长比数字。

| 用户想知道 | 3D 行不行 |
|---|---|
| 它在哪、哪一块出事了 | ✅ |
| 卡在哪一步 | ✅ |
| 谁连着谁、哪一层出事了 | ✅ |
| 整体量级，一眼看出谁最大 | ⚠️ 可以，但必须按 S4 的 4 条保险做 |
| A 比 B 多多少、这个月涨了还是跌了 | ❌ 留给旁边的 2D 图表 |

三条都过才上 3D，有一条不过就回到 L1–L4：

1. 用一句话说得出这个场景回答哪个问题。
2. 精确的数字比较和趋势已经放进 2D 面板。
3. 把 3D 关掉，光靠列表和数字还能把事办完。

## 2. 四种场景画法（S1–S4）

| 编号 | 信息类型 | 场景长什么样 | 3D 回答什么 |
|---|---|---|---|
| S1 空间 | 仓库、工厂、园区、楼层、门店 | 按真实布局摆的微缩模型 | 它在哪、哪块出事 |
| S2 流程 | 订单流转、供应链、销售漏斗、审批 | 一排站台，每个环节一站，货在站台之间流动 | 卡在哪一步 |
| S3 结构 | 系统架构、组织、产品模块 | 上下叠起来的 2–4 层平台，模块是板上的方块，连线表示依赖 | 谁连着谁、哪层出事 |
| S4 柱子城市 | 各区业绩、各店销量这类纯数量 | 一片高低不同的柱子 | 整体量级、谁最大 |

**S1 空间**：位置照真实布局，比例可以夸张（设备放大到认得出），相对位置不能错。只放「会出现在列表里的东西」和认路必需的墙、门、路。

**S2 流程**
- 站台沿一条轴排成一排，从左到右就是先后顺序。超过 7 站折成两排（起始值）。
- 每站是一块薄平台、一个代表这一步的物件、头顶一个数字（这一步现在有几单）。
- 排队多少用站前堆的小方块表示，最多堆 10 个，再多写「+N」（起始值）。
- 卡住的那一站整块上状态色。转化率、耗时这些精确数字放 2D 面板。

**S3 结构**
- 每层一类东西，例如入口、应用、数据、基础设施。层与层之间留空，看得见上下关系。
- 连线只画直线和直角折线，默认淡灰。选中一个模块，只亮它的上游和下游。
- 选中某一层时，其他层淡到只剩轮廓，不然上层会挡住下层。
- 超过 4 层，或一层超过约 8 个模块（起始值），就拆成两个场景，或者让用户先选层。

**S4 柱子城市**：最有气势，也最容易让人读错数，4 条保险一条都不能少。
1. 每根柱子顶上常显数字，不是悬停才出现。
2. 旁边必须有一张同一份数据的 2D 图（柱状图或排序列表）。点柱子和点图里的条，是同一个「选中」。
3. 所有柱子底面一样大，高度从 0 起，只有高度代表数值。
4. 高的放在离镜头远的那一角，矮的放前面，总数不超过约 20 根（起始值）。几何事实：这个俯角下，高 h 的柱子会挡住它正后方 1.41h 远的地面（h ÷ tan 35.264°）。

正交投影没有近大远小，同样高的柱子放在屏幕哪里看起来都一样高，这是它比透视 3D 图表好的地方。

## 3. 先分清是哪种屏

三种屏的场景画法一样，差别在字号、镜头会不会自己动、装饰动画留不留。项目没说就问一句。

| | 演示（给客户看） | 后台（每天坐着用） | 大屏（挂在墙上） |
|---|---|---|---|
| 谁在操作 | 讲解的人点，客户看 | 调度、运维自己点 | 没人点 |
| 动效人格 | 有表现力，惊喜只放在开场 | 克制，不回弹 | 克制，不回弹 |
| 镜头自己会不会动 | 打开时推近一次 | 不会，只在用户选中时动 | 自动巡场，每 20–30 秒停到下一个区域（起始值）；有异常就停在异常上；有人动了鼠标就停巡 |
| 装饰性流动（车、传送带） | 可以有，用 mock 数据驱动，必须能暂停 | 没有，真数据变了才动 | 没有，真数据变了才动 |
| 字号 | 正常 | 正常 | 按视距放大，见下 |
| 留哪些面板 | 全套 | 全套，列表是主角 | 只留顶部数字和告警列表；搜索、筛选、详情里的操作全删 |

**大屏字号怎么算**：CSS 规范把 1px 定成手臂距离（约 0.71 米）下的一个固定视角，那时 1px 约 0.26 毫米。

需要的 px = 桌面上的 px ×（视距 ÷ 0.71 米）×（0.26 ÷ 这块屏每个 CSS 像素的毫米数）

例：55 寸屏、网页宽 1920px，每个像素约 0.63 毫米；站在 3 米外看，16px 的字要放到约 28px。算完一定要到现场，站在最远的位置看一遍。

**4 个状态**

| 状态 | 场景 | 面板 |
|---|---|---|
| 加载中 | 白模先出来，不带状态色；不用转圈盖住整屏 | 数字和列表用骨架占位 |

| 数据断了 | 状态色全部褪成灰，物件停在最后的位置 | 顶部一条提示：数据停在几点、正在重连 |

## 5. 镜头

- 用正交相机，没有近大远小。相机位置的三个分量相等（例如 `[50, 50, 50]`）并看向原点，俯角就是 35.264°，这个角度锁死。
- 允许：平移、缩放、每次转 90°（4 个固定朝向）。不允许：自由旋转。能随便转就不是等距了，也容易转到看不懂的角度。
- 缩放要有上下限：最远看得到整个场景，最近看得清一个物件。

| 操作 | 触屏 | 鼠标 / 触控板 | 键盘 |
|---|---|---|---|
| 平移 | 单指拖 | 左键拖 | 方向键 |
| 缩放 | 双指捏合 | 滚轮 | `+` / `−` |
| 转 90° | 不做 | 屏幕上的 ↺ ↻ 按钮 | `Q` / `E`（起始值） |
| 选中 | 点一下 | 点一下 | 走列表：上下键移动，镜头跟着 |
| 回到全景 | 屏幕上的按钮 | 屏幕上的按钮 | `0`（起始值） |

拖动和捏合都要有不用拖的替代办法（缩放按钮、回到全景按钮、列表），这是 WCAG 2.5.7 的要求。

## 6. 画风：白模 + 1 个强调色

像建筑沙盘。所有物件同一种颜色，靠形状认东西；颜色只留给三件事。

| 谁能上色 | 用什么色 |
|---|---|
| 选中的那一个、正在流动的东西 | 强调色 |
| 警告 | 橙 |
| 异常 | 红 |
| 其余全部，包括「正常」 | 不上色 |

**两套款式**（起始值，括号里是对地面的对比度）

| 项 | 浅色款 | 深色款 |
|---|---|---|
| 适合 | 演示、后台、室内场景 | 大屏、监控、长时间盯屏 |
| 地面 / 场景底 | `#E8EEF5` | `#0B1026` |
| 白模本体 | `#F4F6F8` | `#2A3556` |
| 棱线 | 不画，靠明暗面分形 | 必画，`#7C8DB5`（5.67:1）。本体和底只差 1.56:1，没有棱线看不出形状 |
| 强调色 | `#2563EB`（4.43:1） | `#00D4FF`（10.63:1） |
| 警告 | `#C2410C`（4.43:1） | `#F97316`（6.71:1） |
| 异常 | `#B91C1C`（5.54:1） | `#FF4444`（5.52:1） |
| 面板文字 主 / 次 | `#1A1A1A` / `#4A4A4A` | `#FFFFFF` / `#A0AEC0` |
| 面板 | 白玻璃 | 深玻璃，或按 L4 用不透明、亮一档的灰 |

- **强调色用客户的品牌色**，换行业只换这一格。品牌色是橙、红色系，或者对地面不到 3:1（WCAG 1.4.11），就退回款式自带的强调色。
- **状态不能只靠颜色**（WCAG 1.4.1）。橙和红互相只差 1.25:1，色弱用户分不出。警告在物件头顶加三角牌，异常加圆牌，列表里同时写字。
- **标签只给选中的和出事的**，不给每个物件挂牌子。S2 的站台数字和 S4 的柱顶数字是例外。
- **材质**：哑光，不反光，不贴图（粗糙度 0.6–0.8，金属度 0，起始值）。小圆角，约为物件短边的 3–5%（起始值）。
- **光**：一盏主光加一层环境光，让每个方块的顶面最亮、两个侧面一亮一暗。三个面三个明度，形状就读得出来。
- **阴影**：只要一层柔和的接触阴影，物件不动时只算一次。
- **深色款的发光**：只让选中的和出事的发光，不要整屏泛光。
- **不要的**：星空、天空、云、镜面反射、渐变天幕。说不出回答什么问题的装饰（树、路灯）不放。

## 8. 联动：列表、场景、详情共用一个「选中」

全页只有一个「当前选中的是谁」，三块都读它，谁也不自己另记一份。

| 发生了什么 | 列表 | 场景 | 详情 |
|---|---|---|---|
| 点列表里一行 | 这一行选中 | 镜头滑过去，物件描边，其余变淡 | 打开 |
| 点场景里的物件 | 对应那行选中并滚到看得见 | 同上；物件已经在视野里就不动镜头 | 打开 |
| 点场景空白处，或按 Esc | 取消选中 | 去掉描边，恢复原样，镜头不动 | 收起 |
| 鼠标悬停在物件上（只有桌面） | 对应那行浅色提示 | 物件头顶出名字 | 不变 |
| 数据触发告警 | 新增一行，排到最前 | 物件上状态色，脉冲 3 下 | 不自动打开 |

- **场景里能点的每个物件，列表里都要有一行。** 键盘和读屏走列表；画布对读屏是一张图，给它一句文字说明。
- **镜头不抢。** 用户正在拖镜头，或者正在看别的物件，新告警不许把镜头拉走。只有大屏会自己停到异常上。
- **多个告警同时出现**：都上状态色，列表按严重程度排，镜头等用户选。
- 物件前后重叠时，只让离镜头最近的那个响应点击。

## 9. 动效：只有 3 处

数值全部取自 `references/core/params.md`。项目有动效规格就写进规格的「已采用」。

| 动效 | 什么时候 | 看到什么 | 参数 | 减少动态时 |
|---|---|---|---|---|
| 镜头滑到选中 | 选中变了，而且物件不在视野里 | 镜头平移过去，必要时拉近 | 时长落在「全屏切换 200–500ms」一档；自己写补间用 `--ease-in-out` | 直接切到位，不滑 |
| 选中描边 | 选中变了 | 选中的描强调色边，其余往地面色靠一档；带状态色的不变淡 | 同 P8：200ms `--ease-out` | 保留，它只是颜色变化 |
| 告警脉冲 | 物件**刚**变成警告或异常的那一刻 | 状态色亮起 300ms、回落 300ms，重复 3 次（约 1.8 秒），然后停在常亮 | 颜色变化用 `ease` | 不脉冲，直接常亮 |

- **镜头滑到一半用户又点了别的**：从当前位置直接转向新目标，不先回原位（同 G5）。
- **键盘上下键连续扫列表时不滑镜头**，只换描边；停下约 300ms（起始值）没再按才滑。这是频率关。
- **页面打开时本来就异常的不脉冲**，直接常亮。脉冲只表示「刚刚发生」。
- **脉冲为什么是 3 下**：WCAG 2.3.1 规定每秒闪烁不超过 3 次，2.2.2 规定自己开始、超过 5 秒的闪烁必须能暂停。3 下 1.8 秒，两条都不碰。
- 其余变淡时不要用半透明：半透明物件互相叠着容易前后画错。往地面色靠一档就够。
- 告警同时让顶部的告警数字翻一下（G3）。不做抖动，它不回答任何问题。

**演示屏多 2 处**（后台和大屏不要）

| 动效 | 看到什么 | 规矩 |
|---|---|---|
| 开场推近 | 镜头从略远（缩放 0.85 → 1，起始值）推到全景，物件整体淡入 | 500ms `--ease-out`；只在第一次打开播一次；减少动态时不播 |
| 流动 | 车、传送带上的货匀速走，不加缓动 | 必须有暂停键（WCAG 2.2.2）；减少动态时默认静止 |

## 10. config 能换什么、不能换什么

| 改 config 就行 | 要写代码补 |
|---|---|
| 浅色款还是深色款、强调色 | 表里没有的新物件 |
| 是哪种屏（演示 / 后台 / 大屏） | 新的场景画法 |
| 顶部放哪几个数字、单位 | 新的面板类型 |
| 物件摆在哪、朝哪边、绑哪条数据 | |
| 列表放什么、按什么排 | |

所以对客户的说法是「换行业 = 换 config + 补几个物件」，不是「换个 config 就行」。同一个行业换客户，才是真的只改 config。

## 11. 手机和平板

| | 桌面视图 | 手机视图 |
|---|---|---|
| 场景 | 铺满窗口 | 占上半屏，高度约 45%（起始值），不跟着页面滚 |
| 列表和详情 | 左右两块浮动面板 | 底部弹层（M7）：收起时露出告警数和第一行；拉到一半看列表；选中后弹层里换成详情 |
| 顶部数字 | 一行 3–4 个 | 留最重要的 2 个，其余横滑 |
| 镜头 | 平移、缩放、转 90° | 单指平移、双指缩放，不能转；给一个「回到全景」按钮 |
| 物件名字 | 悬停出现 | 点选之后才出现 |
| 时间轴 | 底部一条 | 收进弹层 |

平板横屏按桌面视图排，竖屏按手机视图排，场景可以占到 55%（起始值）。

**手机上的硬规矩**
- 物件的可点区域不小于 44×44px。小物件加一个看不见的大点击体。
- 场景区自己接管触摸（`touch-action: none`）。页面本身不需要滚动：场景固定，弹层里面滚。
- 弹层拉满盖住场景时，暂停场景渲染。
- 后处理（发光、柔边描边）默认关，像素比封到 1.5（起始值）。

**跑不动时换静态图**：用同一个角度预先渲染一张场景图，物件位置上放可点的圆点，点了一样选中、一样开详情。两种情况自动换：浏览器开不了 3D；帧率一直上不去。代价是没有镜头滑动和流动，场景布局一改就要重新出图。

## 12. 怎么写

装任何包之前先问用户。先看项目的 React 版本：`@react-three/fiber` 9.x 配 React 19，8.x 配 React 18；`@react-three/drei` 10.x 要 fiber 9（2026-10 查的，动手前再看一眼）。

**Web 和 WebView**

```jsx
// 相机位置三个分量相等 = 俯角 35.264°；极角 = 90° − 35.264°
const POLAR = Math.acos(1 / Math.sqrt(3))

<Canvas orthographic frameloop="demand" dpr={[1, 2]}
        camera={{ position: [50, 50, 50], zoom: 40 }}
        fallback={<StaticScene />} onPointerMissed={clearSelection}>
  <CameraControls makeDefault minPolarAngle={POLAR} maxPolarAngle={POLAR}
                  minZoom={20} maxZoom={120} />
  {/* 物件 */}
</Canvas>
```

`zoom`、`minZoom`、`maxZoom` 是起始值，按场景大小调。

| 要做的事 | 用什么 |
|---|---|
| 正交相机、没东西动就不渲染 | `Canvas` 的 `orthographic`、`frameloop="demand"` |
| 平移、缩放、锁俯角 | drei `CameraControls`：左键设成平移（`ACTION.TRUCK`），单指 `TOUCH_TRUCK`，双指 `TOUCH_ZOOM_TRUCK` |
| 镜头滑到选中、转 90° | 同一个组件的 `moveTo`、`fitToBox`、`rotateAzimuthTo`，把「要不要过渡」那个参数传 `true`。过渡快慢调 `smoothTime`，它是「大约多久到位」，默认 0.25 秒 |
| 小圆角方块 | drei `RoundedBox` |
| 大量重复的物件 | drei `Instances` / `Instance` |
| 选中描边 | drei `Outlines`，开 `screenspace` 让线宽不随缩放变。要柔边光晕才换后处理的 `Outline` + `Selection` / `Select`，并给 `EffectComposer` 设 `autoClear={false}` |
| 深色款棱线 | drei `Edges` |
| 物件头顶的名字和数字 | drei `Html`（只有网页有） |
| 接触阴影 | drei `ContactShadows`，物件不动时 `frames={1}` |
| 深色款发光 | `@react-three/postprocessing` 的 `Bloom`，`luminanceThreshold={1}`，只有调亮并关掉 `toneMapped` 的材质会亮 |
| 点物件、点空白 | 物件上 `onClick` 里调 `e.stopPropagation()`，后面的物件就不响应；空白用 `Canvas` 的 `onPointerMissed` |
| 开不了 3D、跑不动 | `Canvas` 的 `fallback`；drei `PerformanceMonitor` 的 `onDecline`、`onFallback` |

- 面板的进出场用项目已有的动效库，写法见 `references/build/web.md`。
- Capacitor、Electron、Tauri 写法相同。在最旧的目标引擎上确认 3D 开得了，开不了就走静态图；低端 Android WebView 默认走静态图（见 `references/core/platforms.md` 第 3 节）。

**RN / Expo**

- `Canvas` 从 `@react-three/fiber/native` 引入，底层是 `expo-gl`；drei 从 `@react-three/drei/native` 引入。
- `drei/native` 没有 `Html`。物件头顶的名字改用普通 `View` 盖在画布上。
- iOS 模拟器的 3D 渲染不可靠，R3F 文档要求用真机测。
- 镜头控制组件在 native 下的支持情况官方文档没写明：动手前先在真机上跑通单指平移和双指缩放；不行就用 Gesture Handler 直接改相机的位置和 `zoom`。
- 玻璃面板用 `expo-blur`，底部弹层和手势见 `references/build/rn.md`。

## 13. 性能

1. **没东西在动就不渲染。** `frameloop="demand"` 只在有变化时画一帧，省电、风扇不转。drei 的镜头控制会自己触发重画；自己改了物件的值要调 `invalidate()`。演示屏有流动时才连续渲染。
2. **像素比封顶。** `dpr` 默认 `[1, 2]`，手机封到 1.5（起始值）。
3. **重复的物件合并成一批画**（`Instances`）。
4. **阴影只算一次。**
5. **玻璃面板别多。** 场景每重画一帧，盖在上面的模糊就要重算一次。同屏不超过 3 块（起始值）；跑不动先把玻璃换成不透明面板，再考虑关 3D。
6. **后处理只在需要时开**，手机默认关。
7. **盯着帧率自动降级**：掉了先降像素比、关后处理；还不行就换静态图。

## 14. 常见翻车

- ❌ 用户能随便转镜头 → 转两下就不是等距了。只许 90° 一跳。
- ❌ 每个物件一个颜色 → 出事的那个淹没在彩色里。
- ❌ 告警一直闪 → 盯久了烦，几个一起闪更看不出先处理谁，也违反 WCAG 2.2.2。
- ❌ 只靠橙和红区分警告和异常 → 色弱用户分不出。加形状和文字。
- ❌ 每个物件头顶都挂标签 → 一片牌子，哪个都看不清。
- ❌ 把数字比较做成柱子，旁边不配 2D 图 → 客户读错数。
- ❌ 场景里能点、列表里没有 → 键盘、读屏、旧手机全都用不了。
- ❌ 数据断了场景还像活的 → 状态色要褪灰，并写明停在几点。
- ❌ 新告警把镜头拉走 → 用户正在看的东西丢了。
- ❌ 对客户说「换个 config 就能换行业」→ 实际要补物件，见第 10 节。
- ❌ 直接抄上面的色值，无视项目已有的 `DESIGN.md` → 同一个产品出现两套颜色。
