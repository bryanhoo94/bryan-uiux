把一条看不见的规则、算法或流程，发明成一台真机器来讲：机器怎么动，概念就怎么运作。比如「没变就跳过」画成一把弹子锁，弹子全对齐，锁芯才转。画风是单色等距仪器图：零件很多，四档明暗，整张只亮 1 个零件；装在一张卡片里，左上 `Fig 1`，右上标题，左下提示，右下实时读数。用在说明页、文档、文章、提案、落地页「它怎么工作」那一节。

英文原文、零依赖的 Node 工具包、检查脚本和 9 个示例的源码在 `references/visual/explain-objects/`（入口是 [explain-objects/index.md](explain-objects/index.md)）。这份管：用不用、画什么、本库加的规矩、桌面和手机视图、动效、怎么放进项目。

- 时长、曲线只从 `references/core/params.md` 取，工具包里的已经改好了。
- 读的人默认是客户，不懂技术：先一眼认出这是什么机器、点哪里，再谈零件多精细。

## 1. 用不用（自己判断，不问用户）

按下表从上往下对，第一条对上的就是。

| 项目里看得到的 | 用不用、放哪 |
|---|---|
| 用户点名：「讲概念的实物图」「把这条规则画成一台机器」「Fig 1 那种仪器图」，或者发了这类截图 | 用。点名就算确认过 |
| 项目里已经有自己的插画风格（`illustrations/`、成套的插图 SVG、Lottie） | 不用，跟项目现有的风格 |
| 说明页、使用说明、文档、文章、提案里，有一段在讲**一条看不见的规则、算法或流程**：怎么判定、为什么被挡、额度怎么算、为什么快 | 用，放在讲这件事的那一节，一节一张 |
| 落地页卖软件、SaaS、API，有一节讲「它怎么工作」 | 用，放那一节。首屏不放 |
| 要讲的是**一件实物产品本身**（POS 机、智能锁、设备），让人按一下看结果 | 不用这套，按 `references/visual/glow-objects.md` |
| 空状态、引导卡、开启某个功能的弹窗 | 不用，按 `references/visual/illustrations.md` 画小线稿 |
| dashboard 日常页、值班大屏、每天要用很多次的工作台 | 不用：那里的注意力留给数据和操作（频率关）。带数据的 3D 场景按 `references/visual/isometric-scene.md` |
| 做不了 Node（只能改后台、无代码建站） | 不用这套：图是用 Node 跑脚本生成的。改用 `references/visual/glow-objects.md` 的 2D 模板，浏览器直接打开 |

- **一屏只出现 1 张**：长的说明页可以有好几张（Fig 1、Fig 2），但两张之间要隔开，桌面和手机上都不会同时出现在一屏里。同一组图用同一个比例尺（原版的要求）。
- **整张图算这一屏的「1 样」高亮**：图里只亮 1 个零件；图所在的那一节不再放别的强调色元素。
- 选完用一行告诉用户，例如：「『小心同行』那一节放一张钥匙板：这一节讲『同一个卖家挂了几台车』这条规则，现在只有两段字。」

## 2. 画什么：概念 → 机器

动手画之前先写下这 3 样（原版 Workflow 第 2、3 步）：

1. **真的数字**：门槛、数量、单位（例：同一个卖家挂 3 台以上算同行）。项目里查不到就问用户，不编。
2. **一句话**：什么在动，动代表什么（例：「每挂一台车多一把钥匙，钩子往下沉；沉过红线，牌子翻成『同行』」）。
3. **按什么 → 出什么**：读者点哪里、拖什么，看到什么结果，右下读数写什么。

| 要讲的概念 | 画成什么机器 | 亮的那 1 个零件 |
|---|---|---|
| 一个东西服务很多个（一个 GPU 上下文画很多画布） | 龙门绘图仪：一个打印头轮流跑 16 个孔 | 打印头 |
| 没变就跳过（缓存命中） | 弹子锁：弹子全对齐，锁芯才转 | 锁芯 |
| 几样东西各占多少（7 个渲染目标的字节数） | 7 格抽屉柜，每格深度等于它的字节数 | 拉开的那一格 |
| 两步做比一步省（可分离模糊：49×49 次 vs 49+49 次） | 一块钉床印章，旁边两把在导轨上走的梳子 | 正在走的梳子 |
| 按次数判定（同一个卖家挂了几件 → 同行） | 钥匙板：一件一把钥匙，钩子压过红线就翻牌 | 正在翻的牌 |
| 先查自己的，没有再去外面拿（缓存回源、先查库再派工） | 档案柜加一条气动传送管 | 正在管子里走的那张单子 |
| 限额（一天 N 次） | 撕票机：用一次撕掉一张，卷越来越薄 | 正在撕的那张 |

前 4 行是原版画过的；后 3 行是本库补的起点，照样要按上面 3 样写清再画。表里没有的，照这个思路找：这件事在现实里由什么东西来做（锁、秤、柜子、闸、传送带、计数器），画那个东西。不画方框加箭头，不画漏斗、齿轮、盾牌这种符号。

- **原版说的两种失败**：太抽象（叠起来的板、浮着的方块、贴标签的盒子），太扁太素（一块大板几条线）。
- **多大**：原版分 Figure（一个机构，40–80 个零件，一般不到 1 小时）、Hero（80–150 个零件，2–4 小时）、Epic（6 小时以上，不直接做，先给估时和缩小版）。说明页、文章默认做 Figure。

## 3. 本库加的规矩

跟原版不一样的地方，以这里为准。

| 项 | 原版 | 本库 |
|---|---|---|
| 颜色 | 单色；亮的零件深色里是白、浅色里是黑；只有「颜色本身就是要讲的东西」才上色 | 照原版。图里要分好坏两种状态时（车主 / 同行、通过 / 拦下），用项目已有的状态色，不用项目的强调色，强调色留给主按钮 |
| 红色 | 火焰、尾焰这种本来就是红的可以红 | 物理上本来就红的照原版；表示状态时，红色只给错误和危险操作 |
| 深色、浅色 | 两种都出（`--light`） | 跟项目：项目只有深色就只出深色，只有浅色就只出浅色 |
| 项目的底色和字 | 自带一套灰阶 | 项目有 `DESIGN.md`：在包住图的元素上，把 `--fig-page`、`--fig-card`、`--fig-paper`、`--fig-text`、`--fig-strong`、`--fig-muted` 换成项目的 token。其余明暗档是配着原版底色调好的，项目底色跟原版差很多时整组一起调，截图对比，不要只改一个 |
| 自己开始的演示 | 闲着就循环，停手 3.6 秒后又开始 | 进画面后演一遍，5 秒内停在最能说明问题的那一帧；读者动过以后不再自己开始（WCAG 2.2.2）。`examples/` 里的示例还是原版的循环，只学写法 |
| 曲线 | 原版用的是抽屉曲线 | `--fig-ease` 已改成 `--ease-out`；悬停抬起 300ms |
| 读数、提示、标题 | 英文小写、等宽字 | 跟产品的语言，中文产品写中文 |
| 检查 | 自带脚本：截桌面、手机 390、悬停和动作中的几帧，零件检查（`--audit`）和线头检查 | 照原版跑。交付前一定看过桌面 1440px 和手机 390px 两张截图。没有 Chrome 就照 `references/visual/explain-objects/references/verify.md` 的清单人工看，并告诉用户看哪两种宽度 |
| 发布到外面 | 能发到原作者的社区画廊 | 删了，不发到任何外部地方 |

## 4. 桌面视图和手机视图

| | 桌面视图 | 手机视图 |
|---|---|---|
| 卡片 | 跟正文同宽（文章栏 640–760px，起始值）；机器占卡片的 55–65%（原版构图） | 占满宽度，两边留页面边距；390px 宽时机器还要认得出（原版要求） |
| 四个角的字 | 左上 Fig n，右上标题，左下提示，右下读数 | 四个角不变；提示改成「点一下」「拖一下」，不写「悬停」；读数放不下就挪到卡片下面第一行 |
| 操作 | 悬停预览，点击确认，方向键一步一步走 | 点一下就执行；横着拖才拨动机器，竖着滑是滚页面（`touch-action: pan-y`，原版已写） |
| 能点的地方 | 零件本身 | 零件太小就让整张图都能点，点一下走到下一个状态；能点的区域至少 44px |
| 图下面 | 图例，加一段真的说明文字 | 同样；图例一行一条 |

- 平板横屏按桌面视图，竖屏按手机视图。
- 手机上任何宽度都不许有横向滚动条。

## 5. 动效

| 动效 | 什么时候 | 看到什么 | 参数 | 减少动态时 |
|---|---|---|---|---|
| 机器自己的动作 | 读者点、拖、按键 | 零件照真的物理在动：滑过去、压下去、弹一下、指针摆到新读数 | 原版的指数跟随（0.1–0.3 秒到位）和真实弹簧，常数来自被讲的那件东西 | 直接跳到结果，读数照样更新 |
| 进画面演一遍 | 图第一次进入画面，约 1.4 秒后 | 把要讲的那件事做一遍 | 5 秒内停住，停在最能说明问题的那一帧 | 不演，停在起始状态等读者 |
| 拆开看 | 悬停或按键 | 各组件按真实拆装顺序错开飞出，再收回 | 原版的弹簧和每组 35ms 的错开 | 直接跳到拆开的样子 |
| 悬停抬起 | 悬停在一组零件上 | 这组往上抬一点 | 300ms，`--fig-ease` | 不抬 |
| 沿线流动 | 信号、东西沿线在走 | 线上的虚线在流 | 匀速，`linear` | 不流，线直接亮 |

- **机器的动作和拆开的错开不从参数词典取**：它们是被讲的那件东西自己的物理，跟 Matter.js 物理一样属于内容，不是界面动效；参数词典「错开总和 ≤ 300ms」管的是列表入场。界面上的东西（悬停、按钮颜色、焦点框）照参数词典。
- 不在画面里就停（原版已写）。
- 这是低频、拿来看懂的东西，频率关不拦它；放进每天用的工作台就违反频率关，所以第 1 节不放。

## 6. 放进项目

| 项目是 | 怎么放 |
|---|---|
| 没有项目，只要一个演示 | `node examples/…/build.mjs` 那样写一个 build，生成一个 HTML，双击打开，完全离线 |
| 静态站、任何 Web 项目（Vue、普通 HTML…） | 照原版「Standalone HTML」那条：卡片的 HTML（`plateHtml` 的输出）、`kit/iso.css` 和脚本（`kitScript()` 加你的 live 脚本）直接放进页面；或者把生成的 HTML 放进 `public/`，用 `<iframe title="说清它是什么" loading="lazy">` 嵌进那一节 |
| React / Next.js | 原版有现成写法：`kit/` 拷进项目，静态的部分在服务端组件里画，会动的部分一个 client 组件（`references/visual/explain-objects/references/react.md`） |
| RN / Expo | 用 `react-native-webview` 打开生成的 HTML（装之前先问用户），给固定高度，在真机上确认竖滑能滚页面、横拖能拨机器。只要静态的：用 `scripts/capture.mjs` 截一张 2 倍图当图片放 |
| Capacitor、Electron、Tauri | 跟 Web 一样 |
| 要打印、发 PDF | 原版的 `scripts/print.mjs`：海报、图纸、详细版三种 A4，见 `references/visual/explain-objects/references/print.md` |

## 7. 无障碍

- 原版已写好：图的根元素能用键盘聚焦，`aria-label` 说清怎么操作，当前状态用文字写在 `aria-valuetext`；读屏只播状态的变化，不播每一帧的数字。
- 图下面那段说明文字要把整件事讲完：看不到图的人只读这段也能懂。
- 状态不能只靠颜色：读数里写字（「车主」「同行」「已拦下」）。

## 8. 常见翻车

- ❌ 画成方框加箭头 → 发明一台真机器，见第 2 节。
- ❌ 读数、说明里的数字是编的 → 读数、动作、说明都从同一个小模型算出来。
- ❌ 一直循环演示 → 5 秒内停住。
- ❌ 一屏里两张图，或者图旁边还有别的强调色 → 一屏一张，只亮 1 个零件。
- ❌ 放进每天用的工作台 → 换地方，见第 1 节。
- ❌ 产品是中文，读数是英文小写 → 跟产品的语言。
- ❌ 只截了桌面 → 手机 390px 也要截。
