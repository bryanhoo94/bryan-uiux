## 四个角色

| 角色 | 大约占 | 给谁用 | 对应 token | 不许 |
|---|---|---|---|---|
| 底色 | 60% | 页面底、卡片和面板、输入框和表头 | `--page`、`--bg`、`--panel-2` | 纯白、纯黑（质感第 1 条） |
| 结构色 | 30% | 标题、正文、说明文字、导航、页脚、分隔、次要按钮 | `--ink-1`、`--ink-2`、`--ink-3`、`--border` | 靠色相拉开层次：层次靠明暗 |
| 强调色 | 10% | 品牌记忆点：选中的行和 Tab 底、标签底、图标小底座、插画主体 | `--accent-soft`（淡色版） | 满色到处撒 |
| 主按钮色 | 一屏 1 个 | 这一屏的主操作；只读不操作的页面就是那个最重要的数字 | `--accent` + `--on-accent` | 一屏出现两个满色亮点 |

- **「主色」这个词**：本库其他文件和 Material 说的「主色 / primary」，都是主按钮色这一格，**不是** 60% 的底色。写 token 不用 `--primary-60` 这类名字，照上表。
- **满色 `--accent` 只给两种地方**：主按钮；面积比主按钮还小的「当前位置」记号（导航选中的那条线、图表的主系列）。其余要强调的地方一律用 `--accent-soft`，上面的字仍用结构色。
- **百分比是预算，不用量像素**。眯眼看截图：底色占大头，结构色撑起骨架，强调色零星几处，主按钮一眼就找到。
- 状态色（成功 `--up`、警示 `--warn`、错误 `--down`）不算进这四格。红色只给错误和危险操作。

## 四种配色强度怎么填这四格

配色强度就是建议卡上那一行（`references/ux/options.md`）。强度决定哪个颜色坐进哪一格，比例不变。

| 配色强度 | 60% 底色格 | 30% 结构色格 | 10% 强调色格 | 主按钮 | 默认用在 |
|---|---|---|---|---|---|
| Restrained | 中性灰阶，往品牌色偏一点 | 墨色 | 品牌色的淡色版 | 品牌色满色 | 后台、工具、表单 |
| Committed | 中性灰阶 | 品牌色占大区块（首屏、一两条色带），字用墨色 | 第二色或品牌色淡色版 | 在中性区用品牌色满色；在品牌色区块上用墨色或底色反白 | 品牌页 |
| Full | 中性灰阶 | 3–4 个有名字的颜色分区域轮流坐，一块区域一种 | 各区域自己颜色的淡色版 | 全页同一个颜色 | 内容多的品牌页、活动页 |
| Drenched | 品牌色本身就是底 | 墨色或很深的颜色 | 第二色 | 跟品牌色底对比最大的那个，常是墨色或第二色 | 单品广告、活动页 |

Drenched 的底是饱和色，正文放在上面经常不到 4.5:1。正文多的那几段换回中性底，或者正文用墨色并逐对算对比度。

## 主按钮色怎么定

从强调色推出来：色相不变，只调字色和深浅。一个强调色锁全页，主按钮不另找颜色。

1. 先试白字：`--accent` 配白字 ≥ 4.5:1，就定了。
2. 不够就换深字（`--ink-1`）：黄、青柠、薄荷、浅青这类亮色通常走这一步。
3. 两种字都不够（中间调的颜色）：在 OKLCH 里保持色相 H，只把亮度 L 往下调，一次 0.01，调到白字过 4.5:1。调好的这一版就是全站的 `--accent`。
4. 再算按钮跟它周围的底：≥ 3:1。不够的话，浅底上把按钮调深，深底上调亮；调到字又不过线，说明底色和强调色太接近，底色换一档。
5. 品牌色是红色，或离错误红 16° 以内：先过 `product-palettes.md` 第 7 节的撞色检查。

饱和度上限见 `design-dna.md` 的 Hard numeric floors，这里不重复。

**算过的例子**（起始值，底色 `#F6F7F9`，深字 `#14171C`）：

| 强调色 | 白字 | 深字 | 按钮对底 | 怎么定 |
|---|---|---|---|---|
| 蓝 `#2D5BD8` | 5.83 | 3.08 | 5.44 | 第 1 步：白字 |
| 紫 `#7A6FE0` | 4.06 | 4.43 | 3.78 | 两种字都不够 → 第 3 步：L 0.61 → 0.58，得 `#7266D6`，白字 4.58 |
| 浅青 `#3FC5E8` | 2.03 | 8.86 | 1.89 | 第 2 步用深字，但按钮在浅底上快看不见 → 第 4 步：调深到 `#009BBD`，对底 3.05，深字 5.49 |

**不要「调亮让它更抢眼」**：按钮调浅，白字就更看不清。要它更显眼，靠的是它跟周围的对比，还有一屏只有它一个满色。

## 元素 → 角色对照

| 元素 | 用哪个 |
|---|---|
| 页面底 / 卡片、面板 / 输入框、表头、图标小底座 | `--page` / `--bg` / `--panel-2` |
| 标题、大数字 / 正文、表格 / 标签、说明、坐标轴字 | `--ink-1` / `--ink-2` / `--ink-3` |
| 分隔、卡片边 | 先靠底色分层不画线（质感第 1 条），非要线才用 `--border` |
| 导航栏、页脚 | 底色；深色页脚算结构色那一格 |
| 次要按钮 | 结构色描边或纯文字 |
| 选中的行、选中的 Tab 底、标签底、图标底 | `--accent-soft`，字用结构色 |
| 导航选中的那条线、图表主系列 | `--accent`，面积比主按钮小 |
| 正文里的链接 | 结构色 + 下划线，悬停变 `--accent`（起始值；一段话里冒出好几个满色亮点会跟主按钮抢） |
| 主按钮 | `--accent` + `--on-accent` |
| 输入框聚焦 | 质感第 2 条的双环 |
| 成功、警示、错误 | 状态色，不用强调色 |

## 深色模式

不反转亮度。四格各自重定一遍：

- 底色：带一点色调的近黑，分几档，越上层越亮，不用纯黑。
- 结构色：近白，不用纯白；深色下字重降一档（质感 10 条）。
- 强调色：同一个色相，用色盘给的深色版（`product-palettes.md` 第 3 节的 Dark 那一列）。
- 主按钮：字色重新按上面 1–4 步算，浅色模式用白字的，到深色模式常常要换深字。

## 写法

**Web**：色值取自 `product-palettes.md` 的 Cool Slate 灰阶 + Cobalt（起始值）。token 放进项目已有的样式文件；项目用 Tailwind 就写进 `theme`，不另起一个文件。

```css
:root {
  /* 底色，约 60% */
  --page: #ECEFF3;
  --bg: #F6F7F9;
  --panel-2: #DDE2E9;
  /* 结构色，约 30% */
  --ink-1: #14171C;
  --ink-2: #333A46;
  --ink-3: #566175;
  --border: rgba(20, 23, 28, .06);
  /* 强调色，约 10%：淡色版为主 */
  --accent: #2D5BD8;
  --accent-soft: color-mix(in oklch, var(--accent) 12%, var(--bg));
  /* 主按钮：满色只给它 */
  --on-accent: #FFFFFF;
}
.btn-primary { background: var(--accent); color: var(--on-accent); }
.tag         { background: var(--accent-soft); color: var(--ink-2); }
```

**RN / Expo**：RN 没有 `color-mix`，淡色版先算好写成色值。

```ts
export const color = {
  page: '#ECEFF3', bg: '#F6F7F9', panel2: '#DDE2E9',   // 底色
  ink1: '#14171C', ink2: '#333A46', ink3: '#566175',   // 结构色
  border: 'rgba(20,23,28,0.06)',
  accent: '#2D5BD8', accentSoft: '#DCE5F7',            // 强调色，淡色版先算好
  onAccent: '#FFFFFF',                                  // 主按钮上的字
};
```

**算对比度**：Web、RN、Node 都能用。也可以直接看浏览器开发者工具取色器里显示的对比度。

```js
const lum = (hex) => {
  const [r, g, b] = hex.slice(1).match(/../g).map((x) => {
    const v = parseInt(x, 16) / 255;
    return v <= 0.04045 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
};
const contrast = (a, b) => {
  const [hi, lo] = [lum(a), lum(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);   // 只收 #RRGGBB
};
```

**交付**：颜色写进项目的 `DESIGN.md`（格式按 `references/core/design-doc.md`）和上面的 token 文件，不另出 JSON。用户要 Figma 变量时才导出。

## 交付前 4 条检查

浅色、深色两个主题都过。

1. **灰度截图**：主按钮是这一屏**对比最强**的一块，不是「最亮」的一块。浅色页上主按钮本来就比底色深。
   - Web：开发者工具 → Rendering → Emulate vision deficiencies → Achromatopsia，或者临时给 `html` 加 `filter: grayscale(1)`。
   - 手机：iOS 设置 → 辅助功能 → 显示与文字大小 → 色彩滤镜 → 灰度；Android 开发者选项 → 模拟颜色空间 → 全色盲。
2. **逐对算对比度**：正文对底 ≥ 4.5:1（从零定色按 7:1 定）；`--ink-3` 对 `--bg` ≥ 4.5:1；按钮字对按钮 ≥ 4.5:1；按钮对周围的底 ≥ 3:1；图标 ≥ 3:1。
3. **数主按钮**：每一屏满色按钮只有 1 个。同一个操作在导航和首屏都出现时，只有一个是满色。
4. **数满色强调色**：`--accent` 只出现在主按钮和比它小的当前位置记号上，别的强调都是 `--accent-soft`。

要知道「看得出品牌感」没有，找真人看 5 秒、说 3 个词。没人看过就不写「通过」。

## 常见翻车

- ❌ 满色强调色撒在图标、标签、插画、悬停态上 → 跟主按钮抢眼。除了主按钮和当前位置记号，全部换 `--accent-soft`，字用结构色。
- ❌ 为了更抢眼把主按钮调浅 → 白字看不清。白字就调深；按钮浅就用深字。
- ❌ 灰度下找「最亮」的那块 → 浅色页上会把对的方案判成错的。要找的是对比最强的那块。
- ❌ 底色和结构色只差一点色相，靠换色相拉层次 → 层次靠明暗，先算正文对底的对比度。
- ❌ 深色模式直接把亮度反过来 → 四格各自重定，见上面「深色模式」。
- ❌ 首屏导航和首屏中间各一个满色的同一个按钮 → 一屏两个亮点。
- ❌ 吸底操作栏整条刷成强调色 → 只有按钮是满色。
- ❌ 项目有 `DESIGN.md` 还加新颜色、按行业强制换成某个蓝 → 只分角色，客户的品牌色优先。
- ❌ 自己给自己写「5 秒测试通过」「0.3 秒被看到」→ 没测过的不写。
