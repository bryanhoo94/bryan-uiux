1. **骨架 K1–K6**：东西放在哪、先看哪个。**每页一个**，按这一页要回答的问题选（总览页 K1、任务页 K5 可以不同）。

## 骨架 K1–K6：东西放哪、先看哪个

满屏一样大的卡片，数据不少，却看不出先看哪。骨架先定「进来第一眼看什么、然后看什么」，再往格子里填内容。骨架是结构层的结果：先过 `references/ux/ux-laws.md` 的结构四问，删掉说不出「回答哪个问题」的元素，剩下的再摆进骨架。

### 选哪个骨架（自己判断，不问用户）

用户通常不会说要哪个骨架，也不该让他选。先看项目：这一页的数据模型、接口返回的字段、`PRODUCT.md` 里写的用户要做什么。按下表从上往下对，**第一条对上的就是**；都对不上用 K2。

| 项目里看得到的（先看这一列） | 用户这么说 | 这一页要回答的问题 | 选 |
|---|---|---|---|
| 每条数据有开始和结束时间，还挂着人或资源（排班、会议室、设备占用、工单派工） | 看不出谁和谁撞了 | 谁什么时候忙、哪里重叠、哪里空着 | K6 时间轴泳道 |
| 每条数据有一个状态字段，状态有先后顺序（待处理 → 进行中 → 完成） | 不知道进行到哪一步 | 每件事卡在哪个阶段 | K5 看板分列 |
| 数据有经纬度、楼层、货架位、点位坐标，或项目装了地图 / 3D 库 | 图和数字各占一半，画面割裂 | 东西在哪（地图、场景、大图） | K4 画布铺满 + 浮动面板 |
| 页面除了主数据，还有日程、通知、待办这种要一直盯着的 | 一滚下去提醒就没了 | 一边翻数据，一边盯着几件事 | K3 主区 + 粘性窄栏 |
| `PRODUCT.md` 或页面上有一个北极星指标（营收、转化率、在线率），其他数都是解释它的 | 页面没重点，不知道先看哪 | 最重要的那一个数现在怎样 | K1 主次布局 |
| 都不是：有汇总数、有趋势、有明细 | 模块东一块西一块，没有阅读顺序 | 从结论到明细，一路读下来 | K2 横带分层 |

- 选完用一行告诉用户：「这一页用 K5 看板：工单有 4 个状态，要一眼看出卡在哪一步。」用户不同意再换，不要先列 6 个让他挑。
- 用户自己说了中间那一列的话，就按那一行，不管项目里看到什么。

- 一页只用一个骨架。唯一允许的嵌套：K3 的主区里按 K2 从上往下排。
- 说不出这一页回答哪个问题，先回结构层，不要靠换骨架救。
- 下面的取值都是起始值；项目有 `DESIGN.md` 就用它的间距 token。

### K1 主次布局（Hero Module）

- **思路**：首屏只有一个最大的模块，放这一页最重要的那张图或那个数；其余指标缩成小块贴在它右边和下面。进来第一眼就知道看哪。
- **提示词**：主次布局：用 12 列网格，主模块占左边 8 列、两行高，面积超过首屏一半，放这一页最重要的图表或核心指标；右边 4 列竖排两张小指标卡，和主模块一样高；下面一行放 3–4 张等宽小卡。主模块的数字最大，其他卡片的数字小一档
- **参考取值**：主模块 ≥ 首屏面积 50%；卡片间距 16px；主数字和小卡数字的字号比 ≥ 2:1。
- **变体**：主模块放右边，小卡放左边和下面。
- **桌面 / 手机**：平板上主模块占满宽，小卡在下面排两列。手机 1 列，主模块排第一个、占首屏大半，小卡改两列网格排在下面；不要把主模块缩成和小卡一样大，那样重点就没了。
- **别用在**：几个指标一样重要（用 K2 的概览带）；说不出哪个最重要（先回结构层问用户）。

### K2 横带分层（Stacked Bands）

- **思路**：整页从上到下切成三条通栏横带：概览数字 → 趋势图 → 明细列表。视线从上往下走一遍，就从结论读到了细节。
- **提示词**：横带分层：页面从上到下分成三条横贯整宽的横带，第一条一排 3–5 个概览数字，第二条一张大的趋势图，第三条明细表格；横带之间留 48px，横带里的卡片间距 16px
- **参考取值**：带间距 48px、带内 16px；内容最大宽度 1440px 左右，超宽屏两边留白，不然表格一行太长读不了。横带之间怎么区分（空白、底色、明度）按选定的排版方向。
- **变体**：趋势带放最上面（用户关心走势多过今天的数）。
- **桌面 / 手机**：手机仍是三条带：概览数字改两列网格，或横向滑动加 `scroll-snap`；图表限高 240px；明细表格改成卡片列表（`references/core/platforms.md` 第 2.2 节）。
- **别用在**：用户只关心某一个数（用 K1）；三条带的内容互相没关系（那是三个页面）。

### K3 主区 + 粘性窄栏（Sticky Rail）

- **思路**：左边主区放图表和列表，可以往下翻；右边一条窄栏放日程、提醒、动态，主区滚动时它停在原地。要盯的和要翻的分开放，谁也不挤谁。
- **提示词**：主区加右侧窄栏：主区占剩下的宽度，放图表和列表，正常往下滚；右侧窄栏固定 320px 宽，放日程、提醒和快捷操作，用 position: sticky，top 等于顶栏高度，滚动时一直可见；窄栏内容比屏幕高时，窄栏自己在内部滚动
- **参考取值**：窄栏 300–360px 固定宽，主区吃剩下的。下面几条是 sticky 能不能生效的硬条件：
  - 窄栏在 grid / flex 里要加 `align-self: start`，不然被拉成和主区一样高，sticky 不生效。
  - 窄栏的任何一层祖先都不能是 `overflow: hidden` 或 `auto`，否则 sticky 失效。
  - `top` 写顶栏高度，不写 0（写 0 会钻到顶栏下面）；窄栏加 `max-height: calc(100dvh - 顶栏高度)` 和 `overflow-y: auto`。
- **变体**：窄栏放左边。只有左边没有导航侧栏时才行，不然两条栏挤在一起。
- **桌面 / 手机**：屏宽 ≥ 1024px 才分两栏。更窄时（平板竖屏、手机），窄栏内容移到主区顶部，压成一条 C6 摘要胶囊，点开用底部弹层看全部；有待处理的提醒时，胶囊上显示数量。
- **别用在**：窄栏里的东西其实不需要一直看（那就排在主区后面）；窄栏里塞了 3 组以上内容（它又变成第二个主区）。

### K4 画布铺满 + 浮动面板（Full Canvas）

- **思路**：地图、场景或一张大图铺满主区当底层，数字和列表做成几块圆角面板浮在上面，贴着角摆。页面有了前后两层，画面是完整的一张。
- **提示词**：全幅画布：底层一张地图（或大图）铺满整个主区，到窗口边不留白；上面浮 3–4 块圆角面板贴着四个角：左上核心指标、右上筛选、左下趋势小图、右下操作按钮；面板离窗口边 16px，中间留空给画布；每块面板都能收起成一个小按钮
- **参考取值**：面板离边 16px，面板宽 ≤ 360px，所有面板加起来遮住的面积 ≤ 画布 30%。面板用玻璃还是实心按排版方向：玻璃见 `references/visual/glassmorphism.md`；L4 用不透明、比底亮一档的实心面板。
- **变体**：面板沿底边排成一排（画布上半部分更重要时）。
- **地图用现成的**：底层是地图时，不自己接地图引擎，先看 `references/visual/libraries.md` 的 mapcn（标记、弹窗、路线、聚合点都有）；项目里已经有地图库就用项目的。
- **桌面 / 手机**：手机上画布占上半屏，只能点选和双指缩放；面板全部收进一个底部弹层（M7），收起时只露出核心指标一行。画布区的拖动要和页面滚动分开，不能一拖地图整页跟着滚。
- **别用在**：底层那张图不承载信息、只是装饰（那就别铺满）；画布是 3D 场景时，按 L5 和 `references/visual/isometric-scene.md` 做，K4 就是 L5 用的骨架。

### K5 看板分列（Kanban Columns）

- **思路**：内容按状态分成几列并排，每列顶上写列名和数量，下面一摞同样宽的卡片。一件事在哪一列，就说明它走到了哪一步。
- **提示词**：看板分列：按状态分成 4–6 列并排，每列顶上是列名和数量，下面是等宽卡片竖着堆，卡片间距 12px；列宽固定 280px，列多了整个看板横向滚动并按列吸附；列内往下滚时列头固定在顶上；卡片可以拖到别的列
- **参考取值**：列宽 280px，卡片间距 12px，列间距 16px；横向 `overflow-x: auto` 加 `scroll-snap-type: x mandatory`；数量加 `tabular-nums`；拖卡片按 F2 拖拽让位做。
- **桌面 / 手机**：桌面放得下全部列时不出现横向滚动。手机一屏一列，顶上一排分段标签写每列的名字和数量，左右滑或点标签换列；手机上不跨列拖，卡片菜单里给「移到…」。
- **无障碍**：拖拽之外必须有不用拖的办法（卡片菜单里的「移到…」，键盘也能用）；移动后用 `aria-live` 播报「已移到 进行中」。
- **别用在**：状态超过 7 个（先合并状态）；内容没有先后阶段（用列表加筛选）。

### K6 时间轴泳道（Timeline Swimlanes）

- **思路**：顶上一条横着的时间刻度，下面每一行是一个人或一个资源的泳道，事项按开始和结束时间画成长短不一的横条，一条竖线标出现在。谁在忙、哪里撞了、哪里空着，横着扫一眼就清楚。
- **提示词**：时间轴泳道：顶部一条横向时间刻度（例如 08:00–18:00），左边一列是泳道名字，每行代表一个人或一个资源；事项按起止时间画成横条，长度对应时长；一条竖线标出现在的时间；同一条泳道里时间重叠的事项上下错开，并用警告色加图标标出冲突
- **参考取值**：泳道高 40px，横条高 28px。
  - 时间刻度在竖着滚时固定在顶上，泳道名字在横着滚时固定在左边（两个都用 sticky）。
  - 横条的位置和长度直接由时间换算，不手排。
  - 现在线每分钟挪一次，不做持续动画；颜色用深灰，不占用强调色。
  - 冲突用警告色（橙）加 ⚠ 图标，点开写明「和 X 重叠 30 分钟」。不用红：红色只给错误和危险操作。
- **桌面 / 手机**：手机放不下一整天：默认显示现在前后 3 小时，横着滑看别的时段，泳道名字缩成头像固定在左边；顶上加一条「今天 2 处冲突」，点开直接列出冲突。
- **无障碍**：每个横条是可聚焦的按钮，读成「张三，10:00 到 11:30，评审会，和 X 冲突」；另给一个按时间排的列表视图。
- **别用在**：事项没有起止时间（用 K5 或列表）；泳道超过 30 条又不能筛选（先按组筛）。

## 核心原则：只做一个视觉判断

页面看起来散，往往不是内容不够，而是同时做了太多视觉判断：又描边、又阴影、又配色、又调字号，互相打架。每个方案只用**一种**手段区分层级。先定这个判断，再往里填内容。

| 方案 | 唯一的视觉判断 | 不用的手段 |
|---|---|---|
| L1 方格纸 + 玻璃卡 | 材质：玻璃 / 实心 / 斜纹 / 渐变 | 边框、阴影 |
| L2 分组侧边栏 | 空间：组间空白就是分组 | 分割线 |
| L3 一深一强调 | 色彩：一块深色 + 一个强调色 | 其他颜色 |
| L4 暗底明度分层 | 明度：亮暗差就是层级差 | 描边、阴影、颜色编码 |
| L5 等距 3D 场景 | 位置：东西摆在场景里哪里就是信息，颜色只留给状态 | 物件自己的颜色、装饰物 |

## 怎么选方向（自己判断，不问用户）

整个产品一个方向，不混用。先看项目，按下表从上往下对，**第一条对上的就是**；都对不上用 L2。动效人格不在这里定，按 `SKILL.md` 第一步的项目画像；最右一列只写这个方向在动效上要注意什么。

| 项目里看得到的（先看这一列） | 用户这么说 | 选 | 动效上注意 |
|---|---|---|---|
| 数据有坐标、楼层、点位、连接关系，要让客户看懂东西在哪、卡在哪一步、谁连着谁；或者项目装了 3D 库（`three`、`@react-three/fiber`） | 做立体一点；让客户一眼看懂现场 | L5（先过 `references/visual/isometric-scene.md` 第 1 节那道关，过不了退到 L4） | 演示屏只在开场放开；后台和大屏不回弹 |
| 数据实时刷新（WebSocket、SSE、定时轮询）；路由里有 monitor、logs、status、alerts；要长时间盯屏或上墙 | 盯一整天眼睛累；做成大屏 | L4 | 不要会动的背景 |
| `PRODUCT.md` 或页面上有一个北极星指标（营收、转化率、在线率），其他数都在解释它 | 页面没重点 | L3 | 动效只出现在强调色那三处 |
| 导航入口超过 8 个，或路由分成 3 组以上；功能模块多的 SaaS 后台 | 找不到功能在哪 | L2 | 只做反馈，不做装饰 |
| 指标卡多、要分出主次，而且是品牌感强的产品或演示用 | 太平了，没层次；高级一点 | L1 | 进场淡入 + 轻微上浮，不回弹 |

- 选完用一行告诉用户：「整个后台用 L2：导航入口有 12 个，靠分组之间的空白分清楚。」用户不同意再换，不要先列 5 个让他挑。
- 用户自己说了「用户这么说」那一列的话，就按那一行，不管项目里看到什么。

### L1 方格纸 + 玻璃卡

- **思路**：底色铺一张 44px 方格纸，卡片做成半透明白玻璃浮在上面，格线透得过来。用材质的层次代替边框和阴影来定义层级。
- **关键特征**：
  - 44px 方格纸铺满整个窗口，四周不留外框。
  - 卡片是半透明白色玻璃，能看到下面的格线。
  - 顶部指标不等大，按数值排成递增的阶梯色块。
  - 实心 → 斜纹 → 渐变，三种填充区分三个层级。
- **提示词**：页面底色用 44px 方格纸铺满，不留外框。卡片做成半透明白玻璃浮在上面，底格线可见。顶部指标按数值排成递增阶梯色块，用实心、斜纹、渐变三种填充方式区分层级。
- **适用**：数据量大、需要一眼看清指标优先级的后台。阶梯式布局本身就在说「哪个数字更重要」。
- **参考取值**（项目有 `DESIGN.md` 就用项目的 token，这些只是没有 token 时的起点）：底色 44px 方格纸，浅灰 `#F5F5F7` / `#EFEFEF` 交替；卡片玻璃按 `references/visual/glassmorphism.md` Token 表里「配 L1 方格纸时」那一行；指标阶梯三档：实心 `#1A1A1A` → 斜纹 `#666` → 渐变 `#CCC → #EEE`。
- **落地注意**：
  - 玻璃要有东西可透（方格纸）才成立，不要在纯色底上用。
  - `backdrop-filter` 在低端 Android WebView 上很贵（见 `references/core/platforms.md` 第 3 节），要降级成不透明白卡 + 更浅的格线。
  - 斜纹和渐变上的文字，对比度仍要 ≥ 4.5:1。
  - 数值变化导致阶梯顺序变化时，用 P6 弧线换列的 FLIP 位移。

### L2 分组侧边栏

- **思路**：导航按功能分组，组与组之间用大段空白区隔，不用分割线。主区首行用超大文字代替传统标题，信息密度高，看起来反而更清爽。
- **关键特征**：
  - 侧边栏按功能分组，组间留大段空白。
  - 组名用 10px 大写无衬线字体（Helvetica 风格）。
  - 栏底固定区放头像和用量条。
  - 主区首行不放标题，放一行超大的细体文字。
  - 右侧三个等大的数字占比，不用饼图，改用横贯整行的分段比例条。
- **提示词**：侧边栏按功能组划分，组间留大段空白，组名用 10px 大写无衬线字体。栏底固定放头像和用量条。主区首行用超大细体文字，右侧并排三个大数字占比，用一条横贯整行的分段比例条代替饼图。
- **适用**：功能模块多、需要清晰导航结构的 SaaS 后台。分组让用户一眼知道「我现在在哪一块」。
- **参考取值**：侧栏组间空白 48px（不画分割线）；组名 10px / 400 / 大写 / `letter-spacing: 2px`；主区首行 48px / 字重 200 / `#1A1A1A`；分段比例条横贯整行，四段按比例分宽，段间 2px 细缝。
- **落地注意**：
  - 10px 大写只用在组名上，加大字距，对比度要够；组名不能是唯一的导航信息。
  - 分段比例条就是 D8 配方，用量条参照 C2 进度底色。
  - 超大细体字在低分辨率屏上容易发虚，要真机看一遍。

### L3 一深一强调

- **思路**：整页只有**一块深色区域**（侧边栏）和**一个强调色**（当前选中项、主按钮、图表命中值）。其他地方全部留白或浅灰，视觉焦点完全靠克制来制造。
- **关键特征**：
  - 全页浅色底，唯一的深色留给侧边栏。
  - 强调色只出现三处：当前选中项、主要按钮、图表中的命中值。
  - 侧栏底部垫一张强调色卡片，把整条栏收住。
  - 其余地方一律不上色，靠明度区分层级。
- **提示词**：整页用浅色底，只给侧边栏一块深色底。全页只用一个强调色，分配给当前选中项、主按钮和图表命中值。侧栏底部放一张强调色卡片收口，其余地方一律不上色。
- **适用**：需要强视觉引导的 dashboard，尤其是用户每次只关注一个核心指标或模块的场景。只亮一处，决策更专注。
- **参考取值**：底色 `#FAFAFA`；侧栏 `#0D0D0F`（全页唯一深色块）；强调色选一个，从 `references/visual/new-page/references/product-palettes.md` 里挑；别用 `#3B82F6` 那种默认蓝，一看就是模板 dashboard。
- **落地注意**：
  - 把「强调色只用在这三处」写进 `DESIGN.md` 当规则，以后新页面不许在别处用。
  - 图表里只有命中值用强调色，其余数据用灰阶明度。
  - 动效也只放在这三处，例如命中值用 G3 数字翻牌。

### L4 暗底明度分层

- **思路**：整页压到近黑，所有层级关系完全靠明度差拉开，不用描边、不用阴影、不用颜色编码。卡片比底色亮一档就够。
- **关键特征**：
  - 底色接近纯黑。
  - 卡片是比底色亮一档的灰，不描边。
  - 主读数是超大数字，单位缩到角落。
  - 日期区不用方格表，改用圆点阵列。
  - 有内容的点顶一颗彩色徽章；空位用斜纹填充。
- **提示词**：做一个深色后台，底色接近纯黑。卡片用比背景亮一档的灰分层，不描边。主读数用超大数字，单位缩到角落。日期区用圆点阵列加彩色徽章标记有内容的项，空位用斜纹填充。
- **适用**：数据监控、实时更新的后台（服务器状态、交易大盘、日志追踪）。暗底减轻长时间盯屏的疲劳，明度分层让重要数据自己跳出来。
- **参考取值**：底色 `#0A0A0A`；卡片 `#16161A`（比底色亮一档，不描边不加阴影）；主读数 64px / 600 / `#FFFFFF`，单位 12px / `#666` 缩在角落；圆点阵列 8px 圆、间距 12px，空位斜纹 `#222`，徽章用强调色。
- **落地注意**：
  - 用近黑，不用 `#000` 纯黑（例如 `#0A0A0A`–`#111111`，起始值）。纯黑配亮字在 OLED 屏上容易出现拖影和光晕。
  - 单位缩到角落，但读屏要读出单位（写进 `aria-label`）。
  - 圆点阵列是 D2 打卡热力格的变体：有内容 = 彩色徽章，空位 = 斜纹。
  - 实时数字用 G3 数字翻牌，每秒都在变的除外（G3 的「别用在」）。

### L5 等距 3D 场景

- **思路**：把一块真实的地方、一条流程或一套系统做成固定俯角的微缩模型，铺满窗口当背景，数据面板浮在上面。模型全部同一种颜色，颜色只留给选中的和出事的。
- **关键特征**：
  - 正交相机，俯角锁在 35.264°，只能平移、缩放、每次转 90°。
  - 白模 + 1 个强调色；橙只给警告，红只给异常，正常不上色。
  - 点列表、点场景是同一个「选中」：镜头滑过去，右边开详情。
  - 精确的数字比较留在旁边的 2D 面板，3D 只回答「在哪、卡在哪、连着谁」。
- **提示词**：做一个等距 3D 场景的 dashboard：正交相机固定俯角，场景铺满窗口；所有物件用同一种哑光浅灰白，只有选中的用强调色描边、警告用橙、异常用红；左侧浮动列表、右侧选中后才出现的详情面板、顶部一条玻璃条放 3 个数字；点列表里一行，镜头平移到对应物件。
- **适用**：有位置、流程或层级关系的信息。纯数字比较不适合，先过 `references/visual/isometric-scene.md` 第 1 节那道关。
- **完整做法**：四种场景画法 S1–S4、三种屏（演示 / 后台 / 大屏）、镜头、配色、部件清单、联动、性能，全部在 `references/visual/isometric-scene.md`。做 L5 必须读它。
- **落地注意**：
  - 场景里能点的每个物件，列表里都要有一行，否则键盘、读屏、旧手机都用不了。
  - 告警脉冲 3 下后停在常亮，不许一直闪。
  - 要装 3D 的 npm 包，装之前先问用户。

## 手机视图

五种方向都要有手机版。**唯一的视觉判断不变，只改排法。** 通用的变法（侧栏变底部 Tab、表格变卡片、边距 16px）见 `references/core/platforms.md` 第 2.2 节。

| 方案 | 手机上怎么排 | 保住什么 |
|---|---|---|
| L1 方格纸 + 玻璃卡 | 卡片改成 1 列；阶梯指标卡三张仍然并排，数字缩一档，阶梯高度差减到 16px（起始值） | 实心 → 斜纹 → 渐变三档材质 |
| L2 分组侧边栏 | 侧栏收进顶栏按钮，展开用 C13 全屏菜单，组和组之间照样只用空白；最常用的 4–5 项另放底部 Tab；首行超大字 48px → 32px；三个大数字改成上下排 | 组间只用空白，不加分割线 |
| L3 一深一强调 | 侧栏变成底部深色 Tab 栏，它就是全页唯一的深色块；侧栏底部的强调色卡片移到页面顶部，或者不要 | 一块深色、一个强调色、强调色只出现在三处 |
| L4 暗底明度分层 | 卡片改成 1 列；主读数 64px → 40px；圆点阵列按屏宽自动换行 | 不描边、不加阴影，只靠明度分层 |
| L5 等距 3D 场景 | 场景占上半屏，只能点选和双指缩放；列表和详情进底部弹层（M7）；跑不动自动换成静态图加可点的圆点 | 白模、颜色只给状态、列表和场景共用一个选中 |

## 能混 / 不能混

可以混，但要看两套的「视觉判断」会不会打架。同时定义同一件事（比如页面底色），就是打架。

| 组合 | 能不能 | 为什么 |
|---|---|---|
| L2 分组侧边栏 + L3 一深一强调 | ✅ 最推荐 | 一个管结构（用空白分组），一个管焦点（强调色）。侧栏正好就是那块唯一的深色 |
| L2 分组侧边栏 + L1 方格纸玻璃卡 | ✅ 可以 | 侧栏管导航，主区管材质，各管各的地盘 |
| L4 暗底明度分层 + L3 一深一强调 | ✅ 可以，质感好 | 明度拉大层级，强调色只做小标记，例如圆点阵列的徽章 |
| L3 一深一强调 + L1 方格纸玻璃卡 | ❌ 不行 | 两套都在决定「页面底色长什么样」：一个要浅灰，一个要方格纸 |
| L4 暗底明度分层 + L1 方格纸玻璃卡 | ❌ 不行 | 一个要干净到一条描边都不画，一个要底下的格线透出来，逻辑相反 |
| L5 等距 3D 场景 + L4 暗底明度分层 | ✅ 可以 | L5 深色款的面板按 L4 做：不透明、比底亮一档、不描边。不用模糊，长时间盯屏也省性能 |
| L5 等距 3D 场景 + L1 方格纸玻璃卡 | ⚠️ 只借玻璃卡 | 面板可以用 L1 的玻璃卡，方格纸不要：页面底已经是场景了 |
| L5 等距 3D 场景 + L2 / L3 | ❌ 不行 | L2、L3 要一条贴边的侧栏，L5 要场景铺到窗口边、面板浮着，两边在抢同一条边 |

## 骨架和方向怎么配

| 骨架 | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|
| K1 主次布局 | ✅ | ✅ | ✅ | ✅ | ❌ |
| K2 横带分层 | ✅ | ✅ | ✅ | ✅ | ❌ |
| K3 主区 + 粘性窄栏 | ✅ | ⚠️ | ✅ | ✅ | ❌ |
| K4 画布铺满 | ⚠️ | ❌ | ❌ | ✅ | ✅ |
| K5 看板分列 | ✅ | ✅ | ✅ | ✅ | ❌ |
| K6 时间轴泳道 | ❌ | ✅ | ✅ | ✅ | ❌ |

- **K1 + L3 最顺**：主模块里的命中值，正好是 L3 强调色出现的三处之一。**K1 + L1**：小卡用 L1 的阶梯色块，次序一眼就清楚。
- **K3 + L2 ⚠️**：左边导航侧栏、中间主区、右边窄栏三列并排，屏宽 ≥ 1280px 才放得下；更窄时窄栏先收成摘要胶囊。**K3 + L3**：深色只给左边的导航栏，右边窄栏保持浅色，不然出现第二块深色。
- **K4 + L1 ⚠️**：只借玻璃面板，不要方格纸（底层已经是画布）。**K4 + L2 / L3 ❌**：它们要一条贴边的侧栏，K4 要画布铺到窗口边，两边抢同一条边。
- **K6 + L1 ❌**：方格纸的格线和时间刻度的竖线是两套格子，对不齐就乱。
- **L5 只配 K4**：L5 就是 K4 的 3D 版。

## 避坑清单

- ❌ 同时用描边 + 阴影 + 配色 + 字号来拉层级 → 四种手段互相打架，页面就散了。
- ❌ 强调色出现在 5 个以上的地方 → 到处都亮，等于哪里都不亮。
- ❌ 方格纸外面再画一圈边框 → 多余，方格纸本身就是边界。
- ❌ L4 里加描边或阴影 → 明度分层的逻辑被破坏。
- ❌ L5 里给每个物件上不同的颜色 → 出事的那个淹没在彩色里。
- ❌ 把纯数字比较做成 3D 柱子，旁边不配 2D 图 → 好看但读不准。
- ❌ 一页里用两个骨架（上半截 K1、下半截 K5）→ 又回到没有阅读顺序。
- ❌ 所有卡片一样大、一样重要 → 没选骨架，先回去选。
- ❌ 直接抄上面的色值，却无视项目已有的 `DESIGN.md` → 同一个产品出现两套颜色。
