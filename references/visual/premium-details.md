界面看着廉价，常常不是布局的错，是几处小地方没抠：到处画线、聚焦是一条刺眼的亮线、深色下字发胖、AI 回答一个字一个字硬蹦、数字一跳就抖、展开时排版炸开、最后一行孤零零一个字、拖拽松手来回晃、复制的对勾赖着不走。

**这 10 条是本库的硬规则**，跟频率关、一屏只高亮 1 样一样，每个项目、每个页面都照做：写代码时就做，不是收尾才查。收尾（`references/visual/finish/index.md` 的 `critique` / `audit`）时再按最后的清单逐条过一遍。

规则里写明的数（1–3%、降 40、6px、120ms、30ms、0.125em、2.5 秒）照用；其余标「起始值」的在真机上调。曲线和 spring 只从 `references/core/params.md` 取。

**有 4 处照原话写会出问题**，本库的写法改了，规则的意思不变：

- 第 2 条：还要留一条透明的 `outline`。平时看不见，照样是「没有亮线」；Windows 高对比模式会删掉所有阴影，这时透明 outline 会变成系统色，键盘用户才看得到焦点在哪。

## 1. 背景分层，代替到处画线

- **做法**：同一个色相的灰做 4 层底色：页面底 → 分区 → 卡片 → 浮起来的（弹层、下拉）。相邻两层的明度差 1–3%（OKLCH 的 L）。拿真机看一眼分不分得出来，分不出来就取 3%。
- **能去掉边框的**：卡片、分区、侧栏、表格的行。靠底色差和留白分开，不画线。
- **不能去掉的**：输入框、复选框、开关这类要让人认出「这里能填 / 能点」的控件。它们的边界跟旁边的颜色要有 3:1 对比（WCAG 1.4.11）；只差 2% 的底色认不出来。
- **不用纯黑 `#000`**：深色底用近黑（`references/visual/dashboard-layouts.md` L4 那段写了取值）。唯一的例外是 E7 挖空文字，它必须是纯黑。
- **深色模式**：越往上的层越亮，不靠阴影分层，因为深底上看不见阴影。
- **桌面 / 手机**：两种视图用同一套 4 层 token。手机上卡片排成一列时，卡片和页面底那一档的差要拿真机看，电脑屏上看得出不代表手机上看得出。

```css
:root {
  --surface-0: oklch(97% 0.004 260);    /* 页面底 */
  --surface-1: oklch(95% 0.004 260);    /* 分区（侧栏、凹下去的区域） */
  --surface-2: oklch(100% 0 0);         /* 卡片 */
  --surface-3: oklch(100% 0 0);         /* 浮起来的，靠阴影 */
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --surface-0: oklch(16% 0.006 260);
    --surface-1: oklch(19% 0.006 260);
    --surface-2: oklch(22% 0.006 260);
    --surface-3: oklch(25% 0.006 260);
  }
}
/* 手动切到深色的 [data-theme="dark"] 写同样四个值 */
```

RN / Expo：同样的 4 个值放进主题对象，按 `useColorScheme()` 取浅色或深色那一组。

## 2. 输入框聚焦：双环，不是一条亮线

- **做法**：聚焦时边框颜色加深一档，外面再套一圈半透明的柔环，看起来是「整个框咬住了」，不是突然多出一条亮线。颜色用品牌色或深灰，不用红色（红色只给错误，见 F11）。
- **一定留一条透明 outline**：Windows 高对比模式会把 `box-shadow` 强制清掉（MDN `forced-colors`），只用阴影的话，开了高对比的键盘用户就看不到聚焦在哪。透明 outline 在高对比模式下会被换成系统色，聚焦就还在。
- **对比**：内环跟背景至少 3:1，否则跟没聚焦分不出来。
- **不做动画**：聚焦是高频操作，直接出现。
- **桌面 / 手机**：桌面上 Tab 键走到哪，环就在哪；按钮、链接用 `:focus-visible`，鼠标点的时候不出现。手机上点输入框也显示同样的环，键盘弹起后输入框要在键盘上方（见 F11）。

```css
.input {
  border: 1px solid var(--border);
  outline: 2px solid transparent;   /* 给高对比模式留的 */
  outline-offset: 2px;
}
.input:focus-visible {
  border-color: var(--ring);                                      /* 内环：加深一档 */
  box-shadow: 0 0 0 3px color-mix(in oklch, var(--ring) 22%, transparent);  /* 外面一圈柔环 */
}
```

RN / Expo：`TextInput` 的 `onFocus` / `onBlur` 切换样式，内环换 `borderColor`，柔环用外面包一层 `View`、多 3px 的半透明边框做。手机上没有键盘 Tab；接了外接键盘的 iPad 要能看到焦点。

## 3. 深色模式字重降 40

- **为什么**：深底上的亮字看起来比浅底上的深字粗、发糊（光渗）。字重往下调一点，两种模式看起来才一样粗。
- **只对可变字体有效**：普通字体只有 400、500、600 这几个整数档，写 560 浏览器会退回 600（MDN 字重回退规则：大于 500 的先往重的找），等于没改。项目用的是普通字体就跳过这一条，不要为了它另加一套字体文件。
- **做法**：字重做成 token，深色下每个 token 都减 40：600 → 560、500 → 460、400 → 360。减完拿深色下最小的那一级字看一次，看不清就在报告里提出来，不要自己偷偷少减。**不要写 `* { font-weight: … }`**，那会把所有字压成同一个字重，层级就没了。
- **亮字也别用纯白**：深色下正文用约 87% 不透明度的白（Material 深色主题的高强调文字），纯白会让光渗更明显。
- **桌面 / 手机**：两边一样。手机屏更亮、离眼更近，降完要在手机上看一次正文。

```css
:root { --fw-body: 400; --fw-medium: 500; --fw-strong: 600; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --fw-body: 360; --fw-medium: 460; --fw-strong: 560; }
}
/* [data-theme="dark"] 写同样三个值 */
body   { font-weight: var(--fw-body); }
strong, .title { font-weight: var(--fw-strong); }
```

RN / Expo：`fontWeight` 只认整百，降不了 40，这条在 RN 上跳过，只做「深色下正文用 87% 的白」。

## 4. 行内小图标和字对齐

- **做法**：正文里夹的小图标，宽高设成 `1em`（跟着字号变），再往下挪 1/8 个字高：`vertical-align: -0.125em`（起始值，不同图标库留白不一样，拿 3 个字号看一下）。
- **按钮里的图标不用这一招**：按钮用 flex 的 `align-items: center` 对齐。
- **桌面 / 手机**：两边一样。手机字号变大时（系统字体放大），图标要跟着变大，所以只用 `em`，不写死 px。

```css
.inline-icon { width: 1em; height: 1em; vertical-align: -0.125em; }
```

RN / Expo：图标和 `Text` 放进一行 `View`，`flexDirection: 'row'`、`alignItems: 'center'`。夹在一段文字中间的图标，用图标字体当成字放进 `Text` 里，才会跟着换行。

## 5. 会变的数字等宽

规则在 `references/core/params.md` 的通用规则里：会变化的数字加 `font-variant-numeric: tabular-nums`。最常漏的地方：计时器、思考用了几秒、倒数、价格、表格里的数字列、分页「3 / 12」。

- **检查字体支不支持**：把「111」和「888」上下放，宽度一样才算生效。不支持的字体，数字那一处换成项目里带等宽数字的字体。
- RN / Expo：`fontVariant: ['tabular-nums']`。

## 6. 正文最后一行不留单字

- **做法**：正文段落 `text-wrap: pretty`（浏览器多算一下，避免最后一行只剩一个字）；标题用 `text-wrap: balance`（几行一样长）。Chrome 117、Safari 26 起支持，Firefox 还不支持（2026-10 查的 MDN），不支持的就照常换行，不用 JS 补。
- **中文标题不手动加 `<br>` 断行**：桌面上断得刚好，到手机上就断在奇怪的地方。
- **桌面 / 手机**：手机一行字少，孤字最多，要在 390px 宽看一次。

```css
p, li { text-wrap: pretty; }
h1, h2, h3 { text-wrap: balance; }
```

RN / Expo：iOS 用 `lineBreakStrategyIOS="push-out"`（系统会把字挤下来，避免最后一行孤字）；Android 标题用 `textBreakStrategy="balanced"`。

## 收尾清单

收尾时逐条过，只列没过的：

1. 卡片、分区没有画线，靠 4 层底色分开（相邻差 1–3%）；输入框、复选框的边界有 3:1 对比；没有纯黑 `#000`（E7 除外）。
2. 输入框聚焦是双环，有透明 outline；按钮和链接用 `:focus-visible`。
3. 深色下字重 token 都降了 40（只限可变字体），正文不是纯白。
4. AI 流式文字按 C21：`blur(6px)`、120ms、每批从 0 数的 30ms 错峰，能跳过。
5. 行内图标是 `1em` 加 `vertical-align: -0.125em`。
6. 会变的数字都有 `tabular-nums`，字体真的支持。
7. 折叠展开是 Grid `0fr` → `1fr`（F5），里面一层一直 `overflow: hidden`。
8. 正文 `text-wrap: pretty`，标题 `balance`，标题里没有手动 `<br>`。
9. 拖拽松手是 `spring-ui`，点赞是 `spring-pop`，复制不弹。
10. 复制的对勾 2.5 秒后换回复制图标（F16），按钮本身不消失。

## 给别的 AI 工具用
