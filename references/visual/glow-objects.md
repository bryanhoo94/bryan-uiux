把一台设备、一个物件或一套系统画成等距小模型：深色底、细线，**只有「开着」的部分亮强调色**，而且它真的能玩：按键出字、灯会亮、鼓机会响、请求顺着线流进服务器。用在落地页、产品介绍、给客户的演示里，讲清「这东西是什么、怎么运作」。

现成的模板、写法和 12 个能玩的 3D 示例在 `references/visual/glow-objects/`（英文原文，入口是 [glow-objects/index.md](glow-objects/index.md)）。这份管：用不用、用哪种画法、本库加的规矩、桌面和手机视图、怎么放进项目。

- 时长、曲线只从 `references/core/params.md` 取，模板里的已经改好了。
- 写 three.js 代码之前先查 `references/build/threejs.md`，别凭记忆写。
- 读的人默认是客户或访客，不懂技术：先让人一眼看懂它是什么、点哪里，再谈好看。

## 1. 用不用（自己判断，不问用户）

按下表从上往下对，第一条对上的就是。

| 项目里看得到的 | 用不用、放哪 |
|---|---|
| 用户点名：「等距发光」「能玩的小物件」「能转能点的 3D」「把这个 .glb 做成线稿」，或者发了这类截图 | 用。点名就算确认过 |
| 项目里已经有自己的插画风格（`illustrations/`、成套的插图 SVG、Lottie） | 不用，跟项目现有的风格 |
| 落地页、官网、产品介绍页卖的是**一件实物**：硬件、设备、门店里摆的东西（POS 机、打印机、智能锁、音箱、相机） | 用，放首屏或产品介绍那一节：画这件产品，能按它的主按钮 |
| 落地页卖的是**软件、SaaS、API**，有一节讲「它怎么工作」（请求进来 → 处理 → 结果出去） | 先按 `references/visual/explain-objects.md`：讲流程和规则归它。项目做不了 Node 时才用这套，放「怎么工作」那一节：把流程画成一台机器（机柜、分拣机、流水线），点一下跑一遍。首屏不放 |
| 给客户的演示页、提案页、作品集，要讲清一台设备怎么用 | 用，一个物件讲一件事。要讲一套系统、一条规则怎么运作 → `references/visual/explain-objects.md` |
| dashboard 的日常页、值班大屏 | 不用。那里的颜色留给「选中 / 警告 / 异常」，这里的「发光 = 开着」会跟它打架。带数据的 3D 场景按 `references/visual/isometric-scene.md` |
| 空状态、引导卡、开启某个功能的弹窗 | 不用，按 `references/visual/illustrations.md` 画小线稿 |
| 列表行、表格、导航、按钮里的图标 | 不用，图标按 `references/visual/libraries.md` 挑 |

- **一页只放 1 个**（同 `references/visual/new-page/references/3d-effects.md` 第 0 节）。要讲几样东西，做成一个物件的几种状态，或者单独一个画廊页（模板自带侧栏切换）。
- **整个物件算这一屏的「1 样」高亮**：物件所在的那一节不再放别的强调色元素，主按钮除外，主按钮跟物件用同一个强调色。物件静止时最亮的只有 1 处。
- 选完用一行告诉用户，例如：「产品介绍那一节放一台能按的发光 POS 机：落地页卖的是收银硬件，现在那一节只有一张产品照。」

## 2. 用哪种画法

| 画法 | 长什么样 | 什么时候选 | 代价 |
|---|---|---|---|
| 线稿发光（默认） | 2D SVG，1px 细线，开着的部分发光；浅色主题下不发光，开着的部分是实心强调色 | 其余情况都选它：离线能开、文件小、手机上也顺 | 不能转视角 |
| Lumen 实心 | 2D SVG，面是带渐变的实心，光画成几何光锥，闲着时自己演示一次主动作 | 首屏要一眼抓人，而且项目是深色的 | 只有深色；浅色项目不用 |
| 真 3D | three.js：能自由转、一键切到真等距、自动转 | 用户要转着看或切等距视角；用户给了 `.glb`；物件要从几个角度才看得懂 | 第一次打开要联网加载 three.js；手机更耗电；要备一张静态图 |

- 判断顺序：用户点名 > 给了 `.glb`（真 3D）> 项目只有浅色（线稿，不用 Lumen）> 首屏要抓人且项目是深色（Lumen）> 其余线稿。
- 要把一件真东西拆开看（爆炸图、剖面、零件标注，比如镜头、发动机）：真 3D，再读 `glow-objects/references/anatomy-builds.md`。

## 3. 每个物件都要真能干点什么

只能看的不做。动手画之前先写下「按什么 → 出什么」。

| 物件 | 按什么 | 出什么（看得见的结果） |
|---|---|---|
| POS 机、刷卡机 | 「刷卡」 | 屏幕从金额变成「已付款」，指示灯亮 |
| 服务器机柜（讲 SaaS、API） | 「发请求」 | 光点沿线进机柜，接活的那台灯亮，读数加 1 |
| 智能锁 | 输密码 | 按下的键亮；密码对了，锁的指示灯亮、锁舌收回 |
| 台灯 | 开关、调光 | 灯罩下面的桌面真的被照亮 |
| 鼓机 | 按鼓垫、播放 | 出声，当前这一步的灯跟着走 |

- 演客户产品自己的主操作，不演跟产品无关的小游戏。
- 读数放右下角，短；产品是中文就写中文（原版的习惯是英文小写）。
- 客户自己的产品名和 logo 可以出现在屏幕上；别家的 logo、商标、产品外形不放。

## 4. 本库加的规矩

跟原版不一样的地方，以这里为准。

| 项 | 原版 | 本库 |
|---|---|---|
| 强调色 | 6 套预设，看的人自己选，记在浏览器里 | 项目有 `DESIGN.md` → 用项目的强调色，作为自定义调色板传进去；没有 → 桌面物件用 Ember，建筑和城市用 City。不用 Rose：红色和偏红的粉只给错误和危险操作 |
| 深色、浅色 | 跟系统，可以切 | 跟项目：项目只有浅色就锁浅色，只有深色就锁深色 |
| 检查 | 不许用浏览器自动检查 | 会话里已经有浏览器工具，就截桌面 1440px 和手机 390px 两张；没有就不装，按原版的办法交给用户，并告诉他看哪两种宽度 |
| 署名 | 页脚有一个「Made with …」链接 | 已删，不加任何署名 |
| 减少动态 | 2D 有，3D 没有 | 都有，见第 6 节 |
| 自己动的（漂浮、闪烁、自动演示） | 一直动 | 5 秒后停住，见第 6 节 |
| 3D 开不了 | 黑屏 | 一句提示，下面一个放静态图的空位：交付前截一张同角度的图放进去（会话里没有浏览器工具，就请用户截一张） |
| 手机上的 3D | 窄屏时右上角的按钮压住按钮面板，按钮约 32px 高 | 按钮面板移到最下面一排，触屏 44px，见第 5 节 |
| three.js 版本 | 0.160.0 | 0.186.1，12 个 3D 示例在浏览器里逐个测过 |

强调色和深浅色怎么锁：

1. **2D**：`window.GALLERY.palette` 传 `[['项目名', 深色强调色, 深色高光, 浅色强调色, 浅色高光]]`；锁深浅色就在 `<html>` 上写 `data-theme="dark"` 或 `"light"`。
2. **3D**：文件靠后「glow colour」那一段的 `ACCENTS3` 换成只有项目强调色的一项；锁深浅色就把最后那行 `setTheme(load('theme') || …)` 换成 `setTheme('dark')` 或 `setTheme('light')`。
3. 只剩一个颜色、深浅色也锁了，就把色板和深浅色按钮藏掉（`.swatches`、`#theme` 设 `display:none`）。3D 用 `?embed` 打开时模板已经藏好了。
| 时长、曲线 | 原版自己的值 | 已按 `references/core/params.md` 改 |
| 模板 | 原版说「只抄不读」 | 照这个做：只改要改的那几处。不要把模板改写成 React、R3F 或者重写外壳，那就回到了凭记忆写 |

## 5. 桌面视图和手机视图

| | 桌面视图 | 手机视图 |
|---|---|---|
| 物件 | 占那一节的主要位置，旁边是按钮面板和说明 | 占满宽度；3D 的按钮在屏幕最下面一排，读数和说明卡叠在按钮上面 |
| 操作 | 点部件、键盘快捷键、悬停时提示能点 | 点部件；没有悬停；键盘提示不显示 |
| 按钮面板 | 物件右边一列，在顶栏下面 | 最下面一排，放不下就横滑；每个按钮高至少 44px |
| 说明卡 | 角落里常驻 | 只显示两行，点一下展开 |
| 3D 转视角 | 左键拖着转，滚轮缩放 | 单指拖着转，双指缩放 |
| 3D 嵌在别的页面里（`?embed`） | 滚轮滚的是页面，不缩放物件 | 竖着滑是滚页面，横着拖才转物件；不缩放 |
| 3D 自动转 | 有开关，默认关 | 有开关，默认关（省电） |

- `?embed` 时页面上只剩物件、按钮、读数和自动转开关：标题、切换物件的标签、键盘提示、色板、深浅色按钮都不显示。
- 平板横屏按桌面视图，竖屏按手机视图（模板按宽度 640px 切）。
- 手机上任何宽度都不许有横向滚动条。

## 6. 动效

模板里已经写好，下面是它们的规矩。数值都在 `references/core/params.md` 的档里。

| 动效 | 什么时候 | 看到什么 | 参数 | 减少动态时 |
|---|---|---|---|---|
| 按下 | 点部件、按快捷键 | 部件往下沉一点，同时亮起，再慢慢暗回去 | 下沉落在「按下反馈 100–160ms」，`--ease-out`；亮和暗是颜色变化，用 `ease`，不超过 300ms | 不下沉，只亮 |
| 光沿着线走 | 信号、请求在流动 | 一小段光顺着线跑过去 | 匀速，`linear` | 不跑，整根线直接亮 |
| 切到等距视角 | 按「Iso view」或 `I` 键 | 镜头滑到正等距的角度 | 「全屏切换 200–500ms」一档，`--ease-in-out` | 直接切到位 |
| 自动转 | 用户打开开关 | 物件匀速转 | 匀速，`linear` | 开关默认关，也不会自己打开 |
| 自己演示一次 | 页面打开时（模板的 `demo`） | 跑一遍主操作，停在亮着的状态 | 跟真按一样的函数 | 不演示，停在起始状态等用户按 |
| 闲着时漂浮、闪烁 | 页面打开就开始：Lumen 的漂浮点、光尘、悬着的卡片和硬币，光标闪、塔顶灯闪、地上的虚线圈转 | 轻轻上下浮、闪、转 | 跑 5 秒就停住：漂浮用模板的 `api.idle(t)` 时钟，CSS 循环动画只播 5 秒以内的次数 | 一开始就不动 |

- **用户按出来、会一直动的，必须有看得见的停止按钮**：循环播放、流量、自动转都算。
- **自己开始的，5 秒内停住**：WCAG 2.2.2 要求超过 5 秒就得能停，模板的做法是直接停。Lumen 闲着时的自动演示，5 秒以后不再开始新的一步，停在亮着的那一步。新写的物件照这个做，漂浮一律用 `api.idle(t)`。
- **按了之后物件自己的机械动作，减少动态时保留**：打字机滑架、磁带转、售货机出货，这些是在演示它怎么工作，属于内容本身（WCAG 2.3.3 允许「必要的」动作）。去掉的是镜头移动、按下的下沉和跑动的光点；镜头拆开例外，直接跳到拆开的样子。
- 这是低频、拿来玩的东西，频率关不拦它；但一个页面只放一个，见第 1 节。
- 有声音的：只在用户按了之后才响（浏览器也不许页面一打开就出声），页面上要有静音开关。

## 7. 用户给了 .glb

先问清用户要的是哪一种：

| 用户要的 | 走哪条 |
|---|---|
| 「做成那种发光线稿」、要跟别的物件统一 | 原版的做法，见 `glow-objects/index.md` 的「Bring your own model」：模型所有材质换成同一个深色本体加细线，颜色只给你指定会亮的部件 |
| 「保留产品本来的样子，只是打光好看点 / 换个配色」 | 不走这套，按 `references/visual/new-page/references/3d-effects.md` §2.B 做模型展示：保留模型自己的材质，色调映射用 `NeutralToneMapping`（商品颜色准），改某一个部件的颜色前先复制它的材质。写法查 `references/build/threejs.md` |

两条都要注意：

- **只有不变形的部件能动**：门、转子、机械臂可以；模型自带的骨骼动画，原版模板不处理。
- **压缩过的模型（Draco、Meshopt、KTX2）原版模板打不开**：按 `references/build/threejs.md` 配好解码器，或者请用户给一份没压缩的。
- **双击打开的单文件**才把模型转成 base64 塞进 HTML（浏览器不许 `file://` 页面去读别的文件），文件会变大三分之一。要上线的页面，模型放成单独的文件，用网址加载。
- 用了别人的模型，许可证要求署名的（例如 CC-BY），在页面上写作者和许可。

## 8. 放进项目

| 项目是 | 怎么放 |
|---|---|
| 没有项目，只要一个演示 | 一个 HTML 文件，双击打开。2D 完全离线；3D 第一次要联网 |
| 任何 Web 项目（静态站、React、Vue、Next…） | 生成的 HTML 放进 `public/`，用 `<iframe src="…?embed" title="说清它是什么" loading="lazy">` 嵌进那一节，宽高比 4:3（起始值）。框架里已经装了 R3F 也一样用 iframe |
| Capacitor、Electron、Tauri | 跟 Web 一样。在最旧的目标 WebView 上确认 3D 开得了，开不了就用静态图 |
| RN / Expo | 用 `react-native-webview` 打开这个 HTML（装之前先问用户）。放在可以滚动的列表里时，WebView 给固定高度，在真机上确认竖滑能滚列表、横拖能转物件。旧安卓机优先用 2D，3D 默认换静态图（同 `references/core/platforms.md` 第 3 节） |

## 9. 无障碍

- 画布和 SVG 要有一句文字说明：它是什么、怎么操作（模板用 `aria` 字段）。
- 每个能点的部件，按钮面板里都要有一个真按钮，键盘和读屏才用得了。有开和关两种状态的按钮，要让读屏知道现在是开还是关（`aria-pressed`）。
- 开着还是关着不能只靠颜色：读数里写字（「开 / 关」「已付款」）。
- 声音不能是唯一的反馈：按下时一定有看得见的变化。

## 10. 常见翻车

- ❌ 物件只能看不能玩 → 原版第一条规矩，先写「按什么 → 出什么」。
- ❌ 亮了但看不出来 → 原版最常见的失败。把开着的状态推到缩略图里也看得出亮。
- ❌ 一页放三个物件 → 一页一个。
- ❌ 放进 dashboard 的日常页 → 发光和状态色打架，换 `references/visual/isometric-scene.md`。
- ❌ 用 Rose 或红色当强调色 → 红色留给错误和危险操作。
- ❌ 物件比首屏的主按钮还抢眼，而且颜色不一样 → 主按钮用物件的同一个强调色。
- ❌ 嵌在落地页里的 3D 吃掉了手机的竖滑，页面滑不动 → 嵌入时加 `?embed`。
- ❌ 把模板改写成 R3F、重写外壳 → 模板是测过的，重写就回到凭记忆写。
- ❌ 3D 开不了时一片黑 → 放静态图。
- ❌ 要上线的页面里塞了几十 MB 的 base64 模型 → 模型放成单独文件。
- ❌ 产品是中文，读数是英文小写 → 跟产品的语言。
