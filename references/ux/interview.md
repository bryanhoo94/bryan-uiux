大多数人不知道自己想要什么设计，也说不出设计词，但一看到就知道喜不喜欢。所以：**先看项目 → 自己定方向 → 用一段大白话说清 → 先做一屏给他看 → 再一次问一题，每题先给推荐，回「好」就照推荐做。** 不让用户从文字菜单里挑：没见过的东西，光看文字是选不出来的。

## 什么时候走这个流程

- 用户说「帮我设计一下」「好看一点」「随便你」「我不知道要什么样」，而要做的页面还不存在。已经存在的页面不满意，走 `SKILL.md` 第零步的改版那一行。
- 或者项目既没有 `DESIGN.md` 也没有动效规格，用户也没说方向。
- 本库任何地方要问用户，问法都按本文件「一次问一题」那一节，见最后一节。

**用户已经点名要什么就不走这里**（例如「加个数字翻牌」），直接做。

## 五件事，先从项目里找答案

每一件都先在项目里找。找得到就自己定，不问；全都找不到的，用最右一列的默认。

| 要定的事 | 项目里看什么就能定 | 定的是什么 | 都看不出来时 |
|---|---|---|---|
| ① 这一屏给谁用，他想干成什么 | `PRODUCT.md` 的 Users；README 第一段；路由名、页面标题、表里的字段 | 结构四问的第一问（`references/ux/ux-laws.md`） | **唯一要在做之前问的一题**，开放题、不给选项：「这一屏是谁在用，他打开是想干成什么？」用他的原话记下来，例如「老板想在手机上花 10 秒看完今天赚了多少」 |
| ② 第一秒的感觉 | `SKILL.md` 第一步的项目画像 | 动效人格，写进动效规格 | 按画像表 |
| ③ 这一屏最重要的一件事 | 已有页面上最大的数字或主按钮；`PRODUCT.md` 里最重要的那个指标；dashboard 是 K1 的那个主数字 | 主角时刻：只有它值得做最显眼的动效，其他都只做小反馈 | 取 ① 那句话里的动词，「看今天赚了多少」就是今天的收入 |
| ④ 动效放多少 | 用的频率：一天打开很多次的工具、后台 → 少；一次性的活动页、品牌页 → 可以有 1 个招牌动效 | 动效的数量和幅度 | 少：1–3 个，只做反馈 |
| ⑤ 参照什么 | 口味档案（`references/ux/taste.md`）里「适合用在」对得上的收藏 | 照它的结构做（怎么分块、什么最大、哪里留白），不照抄它的颜色 | 不参照，按画像做 |

用户自己给了参照（App 名字或链接）：照它的结构做；顺便问要不要记进收藏，要就按 `references/ux/taste.md` 记一条。

dashboard 还要定骨架和排版方向：都按 `references/visual/dashboard-layouts.md` 的信号表自己定。L5 等距 3D 先过 `references/visual/isometric-scene.md` 第 1 节那道关。

## 说出方向：一段话，然后直接做

定完用下面这个格式告诉用户，**说完直接做一屏**，不用等他回复。

> **你会看到**：白底，左边一条深色栏，全页只有「今天赚了多少」最大，只用一个亮色。
> **会怎么动**：按钮按下去缩一下；数字像翻牌钟一样换；列表拉到底弹一下。其他地方不动。
> **根据**：这是后台（路由里有 `/admin`，装了表格库），老板一天要看好几次，所以要稳、不吵。
> **手机上**：左边的深色栏变成底部 Tab，卡片排成一列，大数字缩小一号。

- 「你会看到」只写看得见的东西：颜色、大小、哪里动、怎么排。不写配方编号和专业词，编号写进规格给自己看。
- 「根据」写在项目里看到的证据，一句话。
- 写之前按 `references/ux/ux-laws.md` 的页面类型过一遍检查清单（前 7 条，加上这一屏用得上的第 8–11 条），没过的先自己改好，不用写给用户看。
- 要用图片（生成或下载）的，说完方向后要等用户点头，见 `references/visual/new-page/index.md` §0.B 的 `Images:` 那一行。这是做之前唯一要等的地方。

**先做一屏**，桌面视图和手机视图都给用户看，别一次做完整个项目。做完接着问第 1 题。

## 做完一屏，一次问一题

按设计流程的顺序问：结构 → 视觉 → 动效多少 → 转场 → 交互。上游没定，不问下游。每一层先看项目和刚做的这一屏：定得下来就不问，记成「替你定的」；只有真的有两条路、而且选哪条会改掉用户看到的样子，才问。

| 顺序 | 问什么 | 什么时候才问 | 推荐怎么定（先看项目） | 备选通常是 |
|---|---|---|---|---|
| 1 结构 | 这一屏最大、最显眼的是哪一样 | 有两样一样重要（两个数字，或一个数字和一个主按钮） | 五件事第 ③ 条 | 另一样放最大；或者两样并排（K2 概览带） |
| 2 视觉 | 明暗、疏密 | 项目没有 `DESIGN.md`，画像里看不出（例如既是后台又要上墙） | 项目画像；dashboard 按 `references/visual/dashboard-layouts.md` 的信号表 | 深色大屏 / 浅色；宽松 / 紧凑 |
| 3 动效多少 | 只做反馈，还是加 1 个招牌动效 | 品牌页、活动页，或者用户说过「要生动 / 有记忆点」 | 五件事第 ④ 条 | 加 1 个招牌（只给主角时刻）；或者全都不动 |
| 4 转场 | 页面之间怎么换 | 这一屏会进到下一层（列表点进详情、多步流程、点开大图） | 手机的层级页：M7 手势转场加 G1 边缘滑回；桌面的 Tab：立刻换，不做转场；点开大图：M6 | 立刻换 / 滑进来 / 从原位置放大 |
| 5 交互 | 主角时刻用哪个配方 | 动效规格「已采用」里没有这类组件，用户也没点名 | `references/core/pick.md`「按场景挑」的「先用」那一列，过频率关和目的关 | 「再考虑」那一列里的一个；或者不加 |

- **最多问 3 题。** 要问的超过 3 题，留下最会改变样子的 3 题（通常是视觉、动效多少、交互），其余用推荐，最后列出来。
- 曲线、时长、spring、颜色值这些参数**永远不问**，照参数词典和项目 token。
- 用户点名的、规格里已经定了的、前面答过的，都不再问。

**每一题长这样**

> **第 2 题 / 共 3 题 · 动效**：这页老板一天要开好几次，我推荐**只做按下反馈和数字翻牌**，回「好」就这样做。
> 备选：加 1 个招牌动效，首屏的大数字从 0 滚到今天的值。更有记忆点，但每次打开都要等半秒多。
> 已定：浅色、左边深色栏（第 1 题）。

- 推荐排第一、加粗，跟一句根据（项目里看到的证据）。题目写成回「好」就等于选推荐。
- 备选 1–2 个，要跟推荐真的不一样，写「你会看到什么」和代价，不写配方编号。
- 最后一行「已定」，让用户不用记前面定了什么。
- Claude Code 里有选择框（AskUserQuestion）就用：推荐放第一个，标「（推荐）」；能画个草图的，给每个选项放一张文字草图预览。Codex 或没有选择框时，用上面的文字格式，用户回「好」或编号。

**用户怎么回，你怎么做**

| 用户回 | 做什么 |
|---|---|
| 「好」「ok」「可以」 | 照推荐，问下一题 |
| 「你定」「都行」「随便」 | 照推荐，记成「替你定的」，这一题不再问 |
| 大白话反应：「太素」「太吵」「再活泼一点」 | 翻译成改哪一项：动效按 `references/core/params.md` 的调参表，视觉按 `references/visual/finish/index.md` 的定向修（`bolder`、`quieter`、`colorize`…）。只改那一项，再问下一题 |
| 选了备选 | 只改这一项，把这一屏重做给他看，再问下一题 |
| 选了跟目标冲突的（例如后台每个按钮都要弹） | 一句话说后果（「一天点几百次会很累」），给一个做得到的替代（「只让打卡完成那一下弹」）；他坚持就照做 |

## 定下来之后

1. 用一张小表收尾：**已定**（用户选的）｜ **替你定的**（推荐、用户没反对）｜ **待验证**（要真机或真用户才知道的）。
2. 排版方向写进 `DESIGN.md`，动效写进 `docs/MOTION-SPEC.md`（意图、人格、常量、已采用配方）。这一步就算 `SKILL.md` 第二步说的「确认人格和常量」。
3. 用户后来说「太弹 / 太慢 / 太素」→ 查调参表，只改那一项，别重做。
4. **连着否了两次，或者是空项目（一点线索都没有）而用户只会说「好看」**：做 2–3 屏真的给他比。每屏换一个排版方向和一个动效幅度，不要只差一个颜色；有对得上的收藏，其中一屏标明「参照你收藏的 X」。看得见的样子能选，文字菜单选不了。
5. 定下来之后，后面每个页面都照规格做，不再重新定。

## 别的地方要问用户时

本库别的文件也有要问的时候：装 npm 包、生成或下载图片、`critique` 之后问先改哪几条、写 `DESIGN.md` 时问气质、改版前确认保留什么、`overdrive` 挑方向。搬进来的文件里写着「STOP and ask the user」或「问两轮、每轮三个」的，一律按这里问：

- 一次一题，推荐排第一，回「好」就照推荐。
- 查得到的事实（文件、包的版本、网上能查的）自己查，不问用户。只问要用户拿主意的事。
- 装包和用图片：用户回「好」之前不动手。

## 说话规矩

- 说「按下去缩一下」，不说「press feedback with scale transform」。
- 每个专业词后面跟一个比喻：弹簧回弹 = 像橡皮筋；错峰 = 像多米诺骨牌一个接一个。
- 一次最多说 3 点。
- 用户问「为什么不全加上」→ 用生活例子答：菜里酱放太多，就尝不出菜本来的味道了。
- 用户听不懂就换个比喻，不要把同一句话再说一遍。
