大多数人说不出设计词，但看到推荐和理由就能点头或说不要。全自动的话，同一个项目每次都得到同一个答案，用户也看不到还有什么可选。所以：**先看项目 → 出一张建议卡（推荐 + 备选 + 一句证据）→ 用户回了才动手 → 结构、静态视觉、动效按顺序做 → 每屏交一张交互表。** 回「好」就全用推荐，不懂设计也能用。

## 什么时候出卡

| 入口 | 怎么做 |
|---|---|
| 只打 `/bryan-uiux`、新页面、改版、导航、3D、发光小物件、讲概念的实物图 | **完整卡**：产品风格 + 交互动效 + 最多 2 项。改版要在卡上写清保留什么、换成什么感觉 |
| 只修一样、「质感不够」、「没人点」、「加点交互」、还没点过要改哪几条的打磨 | **短卡**：产品风格 + 交互动效 + 这次要修的那一项 |
| 检查、评审、审计（只看不改） | 不出卡，出报告。报告里要有交互一节，最后推荐先改哪几条 |
| 点名要什么（「加个数字翻牌」），或者检查完回「改前 3 条」 | 不出卡，直接做。做完补一行「这页还可以加 X，要吗」 |
| 问效果叫什么、记收藏、整理截图 | 不出卡 |

卡长什么样、每一行怎么写、哪些选项能上卡，都在 `references/ux/options.md`。本库任何地方要问用户，卡以外的问法按本文件「一次问一题」那一节。

## 五件事，先从项目里找答案

每一件都先在项目里找，找到的就是建议卡上 ⭐ 的证据；全都找不到的，用最右一列的默认。

| 要定的事 | 项目里看什么就能定 | 定的是什么 | 都看不出来时 |
|---|---|---|---|
| ① 这一屏给谁用，他想干成什么 | `PRODUCT.md` 的 Users；README 第一段；路由名、页面标题、表里的字段 | 结构四问的第一问（`references/ux/ux-laws.md`） | **唯一要在做之前问的一题**，开放题、不给选项：「这一屏是谁在用，他打开是想干成什么？」用他的原话记下来，例如「老板想在手机上花 10 秒看完今天赚了多少」 |
| ② 第一秒的感觉 | `SKILL.md` 第一步的项目画像 | 动效人格，写进动效规格 | 按画像表 |
| ③ 这一屏最重要的一件事 | 已有页面上最大的数字或主按钮；`PRODUCT.md` 里最重要的那个指标；dashboard 是 K1 的那个主数字 | 主角时刻：只有它值得做最显眼的动效，其他都只做小反馈 | 取 ① 那句话里的动词，「看今天赚了多少」就是今天的收入 |
| ④ 动效放多少 | 用的频率：一天打开很多次的工具、后台 → 少；一次性的活动页、品牌页 → 可以有 1 个招牌动效 | 卡上第 1 项的数量和幅度 | 少：1–3 个，只做反馈 |
| ⑤ 参照什么 | 口味档案（`references/ux/taste.md`）里「适合用在」对得上的收藏 | 照它的结构做（怎么分块、什么最大、哪里留白），不照抄它的颜色 | 不参照，按画像做 |

用户自己给了参照（App 名字或链接）：照它的结构做；顺便问要不要记进收藏，要就按 `references/ux/taste.md` 记一条。

dashboard 还要定骨架和排版方向：按 `references/visual/dashboard-layouts.md` 的信号表定 ⭐。L5 等距 3D 先过 `references/visual/isometric-scene.md` 第 1 节那道关。

## 出建议卡

1. 读 `SKILL.md` 第一步的项目画像和 `.bryan-uiux/log.json`，知道上次定了什么、否过什么。
2. 按上面五件事找证据，只有 ① 全都找不到时才先问那一题。
3. 按 `references/ux/ux-laws.md` 的页面类型过一遍检查清单（前 7 条，加上这一屏用得上的第 8–11 条），没过的改进建议里，不用写给用户看。
4. 按 `references/ux/options.md` 写卡。
5. **等用户回**。回之前不写代码，也不装包、不生成图片。

## 用户怎么回，你怎么做

| 用户回 | 做什么 |
|---|---|
| 「好」「ok」「可以」 | 全用 ⭐，开始做 |
| 「1B」「2C」 | 只换这一项，其余用 ⭐，开始做 |
| 「维持」 | 骨架、卡片这些不改，交互动效照做 |
| 「你定」「都行」「随便」 | 全用 ⭐，记成「替你定的」 |
| 「看全部」「看全部卡片」 | 列出这一组全部选项，每个一句用途和图鉴编号，⭐ 排第一 |
| 「换方向」 | 把整体风格那一组放上卡，先说清全项目有几页要跟着改。回了才改 `DESIGN.md` |
| 大白话反应：「太素」「太吵」「再活泼一点」 | 翻译成改哪一项：动效按 `references/core/params.md` 的调参表，视觉按 `references/visual/finish/index.md` 的定向修（`bolder`、`quieter`、`colorize`…）。只改那一项，再给用户看 |
| 选了跟目标冲突的（例如后台每个按钮都要弹） | 一句话说后果（「一天点几百次会很累」），给一个做得到的替代（「只让打卡完成那一下弹」）；他坚持就照做 |

**连着否了两次，或者是空项目（一点线索都没有）而用户只会说「好看」**：做 2–3 屏真的给他比。每屏换一个排版方向和一个动效幅度，不要只差一个颜色；有对得上的收藏，其中一屏标明「参照你收藏的 X」。

## 动手之后

1. 按结构 → 静态视觉 → 动效的顺序做。卡上只是选好了交互，动效代码仍然最后写。
2. **先做一屏**，桌面视图和手机视图都给用户看，别一次做完整个项目。
3. 每屏交一张交互表（下一节）。
4. 把这张卡写进 `.bryan-uiux/log.json`，排版方向写进 `DESIGN.md`，动效写进 `docs/MOTION-SPEC.md`（意图、人格、常量、已采用配方）。用户回了卡就算 `SKILL.md` 第二步说的「确认人格和常量」。
5. 用一张小表收尾：**已定**（用户选的）｜ **替你定的**（推荐、用户没反对）｜ **待验证**（要真机或真用户才知道的）。
6. 用户后来说「太弹 / 太慢 / 太素」→ 查调参表，只改那一项，别重做。

## 交互动效每次都设计

这是本库最重要的一部分：只要做或改了一屏，就要设计它的交互，不能留到最后才想，也不能因为赶时间省掉。

每屏交一张表：

| 元素 | 手怎么动 | 给什么反馈 | 桌面 | 手机 |
|---|---|---|---|---|
| 主按钮 | 按下 | 缩一下 | 悬停变深，按下缩一下 | 没有悬停，按下缩一下 |
| 今日收入 | 数据更新 | 只有变的那一位翻牌 | 同手机 | 同桌面 |
| 列表 | 拉到底 | 弹一下 | 没有回弹，到底就停 | 拉到底弹一下 |
| 刷新按钮 | 一天点 100 次以上 | 故意不动，立刻变色 | 同手机 | 同桌面 |

- **这四类这一屏有就要写**：主操作、状态变化（数字更新、提交成功、出错）、等待（加载、空状态）、进下一层（转场）。
- **设计不等于到处都动**。频率关照旧：一天用 100 次以上的操作不加动画，但要有反馈。「故意不动」也是设计，写明原因。
- **Web 和 RN / Expo**：Web 写悬停、键盘和按下；RN / Expo 没有悬停，写按下和手势。写法按 `references/build/web.md` 和 `references/build/rn.md`。
- 点名要什么时，表里只写点名的那个元素。

## 一次问一题

卡以外要问的，都这样问：装 npm 包、生成或下载图片（没写在卡上时）、`critique` 之后问先改哪几条、写 `DESIGN.md` 时问气质、`overdrive` 挑方向。搬进来的文件里写着「STOP and ask the user」或「问两轮、每轮三个」的，一律按这里问：

- 一次一题，推荐排第一、加粗，跟一句项目里看到的证据，回「好」就照推荐。
- 备选 1–2 个，写「你会看到什么」和代价。
- 最后一行「已定」，让用户不用记前面定了什么。
- 曲线、时长、spring、颜色值这些参数**永远不问**，照参数词典和项目 token。
- 查得到的事实（文件、包的版本、网上能查的）自己查，不问用户。只问要用户拿主意的事。
- 装包和用图片：用户回「好」之前不动手。

> **第 2 题 / 共 2 题 · 写 `DESIGN.md`**：这个产品每天要看很久，我推荐**气质写成「安静、可靠」**，回「好」就这样写。
> 备选：「利落、高效」，页面更紧凑，留白少一些。
> 已定：浅色、左边深色栏（第 1 题）。

## 说话规矩

- 说「按下去缩一下」，不说「press feedback with scale transform」。
- 每个专业词后面跟一个比喻：弹簧回弹 = 像橡皮筋；错峰 = 像多米诺骨牌一个接一个。
- 一次最多说 3 点。
- 用户问「为什么不全加上」→ 用生活例子答：菜里酱放太多，就尝不出菜本来的味道了。
- 用户听不懂就换个比喻，不要把同一句话再说一遍。
