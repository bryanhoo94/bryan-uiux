# 口味档案（觉得好看的设计）

这里记的是这份 skill 主人自己觉得好看的东西。`references/visual/libraries.md` 是「去哪看」的客观目录，这里记的是「喜欢什么」。收藏了某个库里的组件，条目就链到那个库。

## 在哪

截图和索引都在本 skill 目录的 `screenshot/` 里：原图随便放，`screenshot/index.md` 是文字索引。

## 什么时候读、怎么读

走全套问选择题时（`references/ux/interview.md` 的 Q5），和出 2–3 套方案时。

1. 只读 `screenshot/index.md` 的文字，不要一上来就打开图片。
2. 按「适合用在」挑出和当前任务对得上的 1–2 条。对不上就到此为止，一张图都不打开。
3. 要看图，只用 Read 打开那 1–2 张。
4. 没有 `screenshot/index.md` 或者是空的：跳过收藏，照常出方案。

## 什么时候写、怎么写

**原图永远不删、不改名、不压缩、不移动。**

**用户说「整理截图」**（图已经拖进了 `screenshot/`）：
1. 列出 `screenshot/` 里的图片，跟 `index.md` 每条「截图」那行比，没出现过的就是新图。
2. 每张新图用 Read 看一次，按下面的格式写一条。「喜欢」先自己猜，末尾加「（猜的）」。
3. 写完给用户一张表：名字 ｜ 类型 ｜ 猜的「喜欢」。用户只改猜错的；改过的换成用户原话，去掉「（猜的）」。

**用户丢来链接或截图，说「记下来 / 收藏这个 / 这个好看」**：只记，不顺手开始做设计。
1. 聊天里贴的截图不会自己变成文件：让用户把图拖进 `screenshot/`；只给了链接，就用浏览器 skill 打开截一张，存成 `screenshot/<短名>.png`。都做不到就写「截图：无」。看不了就直说，不要凭名字猜它长什么样。
2. 只问用户一句：「你喜欢它哪一点：排版、配色、动效，还是整体感觉？」把用户原话照抄进「喜欢」。
3. 按下面的格式写一条。

两种情况都一样：
- 其余字段自己填：「对应配方」查本库各个 references；「适合用在」按它的产品类型写。
- 同一个网站有几处喜欢就记几条；同一样东西再记一次，就更新原来那条，不新增。
- 新条目加在它那个类型的最上面。

## 格式

```
## <类型>

### <名字>（<YYYY-MM-DD>）
- 截图：<文件名>
- 来源：<链接；没有就写「无」>
- 看的是：桌面 / 手机
- 喜欢：<用户原话>（排版 / 配色 / 动效 / 整体感觉）<自己猜的就在最后加「（猜的）」>
- 对应配方：<编号，例如 L4、C1；没有就写「无」>
- 适合用在：<产品类型或页面，例如「产品官网首屏」「记账 App 首页」>
```

类型只用这几个：`Dashboard`、`落地页`、`手机 App`、`组件`、`其他`。都不合适才加新类型。

## 怎么用

- **收藏只决定方向**：挑哪种排版、哪种效果、什么感觉。时长、曲线、spring 仍按 `references/core/params.md` 的参数词典；通用规则（高频操作不加动画、只动 `transform` / `opacity`、支持 reduced-motion）和对比度 ≥ 4.5:1 永远生效。
- **不压过项目自己的规矩**：项目有 `DESIGN.md` 或动效规格时，只借结构和感觉，不改项目的颜色、字体和 token。
- **出方案**：有「适合用在」对得上的收藏，2–3 套方案里固定有一套写明「参照你收藏的 X」，其余几套换不同方向做对比。对不上就不硬套。
- **收藏之间风格矛盾**（例如又喜欢暗黑霓虹，又喜欢浅色极简）：不算冲突，按「适合用在」挑。
- **收藏的对比度不够**：借它的感觉，颜色数值按无障碍规则改，并在方案里说明改了什么。
- **只看过一种视图**（「看的是」只写了手机）：另一种视图按 `references/core/platforms.md` 第 2.2 节自己推，方案里说明是推出来的。
- **链接失效**：截图还在，条目不删，在来源后面注明「链接已失效」。
